# NOW -- t27b: std.mem.eql and std.mem.indexOf on strings (2026-10-05)

## std.mem on strings (Closes #6449)

- `std.mem.eql(u8, a, b)` on two strings lowers as `a == b` (two literals fold, otherwise `__t27b_str_eql`), as t27c's Zig backend prints it verbatim.
- `std.mem.indexOf(u8, h, n) == null` / `!= null` calls a second synthesized fn, `__t27b_str_contains`, with Zig 0.16 `std.mem.find` semantics: a needle longer than the haystack is never found, an empty one always is.
- The index used any other way, another element type, or a non-string operand stays refused as `ExprCall(std.*)`.
- Code in the new submodule `cli/t27b/src/lower/stdmem.rs` with small hooks in `lower.rs`; tests in `cli/t27b/tests/stdmem.rs`, each source run under `t27c test-report` first (3 pass, 2 fail there and here).
