# NOW -- t27b lowers for over a range (2026-10-05)

## t27b: for (a..b) |i|, for i in a..b, for x in xs (Closes #6349)

- `cli/t27b/src/lower.rs` `for_range`: both bounds coerced to usize and evaluated once, the length `b - a` computed with a checked subtraction before the first iteration (Zig panics with integer overflow when b < a), the capture a usize constant per iteration. `StmtForRange` (`for i in a..b`, `for (i in a..=b)`) lowers to the same loop, as t27c's Zig backend prints it.
- `for x in xs`: t27c's parser copies the loop variable into the node name; t27b read that as a labelled loop. A name equal to the sole capture is now the collection loop; any other name stays refused.
- Refused by name: `StmtFor(multi-object)` for `for (xs, ys) |x, y|`; a comptime-reversed range; a signed or negative bound (compile errors in the reference).
- `t27b corpus specs --reference` (t27c built from e0e806a16): counted 615 -> 623 of 720 reference passes, checked (with tests) 338 -> 346, mismatch 0 before and after. Test `for_over_a_range` in `cli/t27b/tests/source.rs`; its verdicts match `t27c test-report`.
