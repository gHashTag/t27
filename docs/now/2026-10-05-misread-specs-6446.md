# NOW -- the 28 specs typecheck refused while gen emitted them, fixed at the source (2026-10-05)

## `tri misread` 35 refused pairs -> 0 (Refs #6446)

- On master `tri misread` reported 35 spec-shape pairs, 0 silent and 35 refused by `typecheck`, in 28 specs. `gen*` never runs typecheck, so all 28 still generated code a backend cannot parse (`pub variants: ,`, `pub GET: ,`).
- Most were list-valued declarations from the trinity `.tri` sources that the parser recovered as untyped fields. Each one is now the declaration it described:
  - `variants : , # a | b | c` -> `enum(u8) { a, b, c }`, with the variants taken from the original `.tri` (eternal_monitor, autonomous_lifecycle, faculty_board, swarm_agents, batch_runner, exit_codes, namespace).
  - `struct { enum : [A, B] }` -> `enum(u8) { A, B }` (logging, logger, color, sort, regex_advanced, async_stream, http, bson, json, msgpack, pipeline_parallel).
  - `enum_type : "enum", values : ,` -> `enum(u8)` (conv2d_layer, dense_layer, cross_entropy_loss, feed_forward). mha_block was refused only through its feed_forward import.
- Other fixes:
  - tools/schema and tools/registry: `enum : [any]?` becomes `enum_values : [str]?`, and the `[K: V]` maps become entry slices (`PropertyEntry`, `ToolEntry`, `PermissionEntry`).
  - igla coder pipeline: the field `invariant` is a keyword, so it is now `invariant_expr`.
  - vsa/sequence_hdc: `map[:]const u8, PackedBigInt>` -> `map<[]const u8, PackedBigInt>`.
- exit_codes and namespace had no tests (L4), so tests were added. The conv2d_layer tests only became runnable once the spec compiled, and its kernel loops indexed past the 2x2 buffer, so the loops and tests now check real values (2/2 pass).
- Ledger: the 25 `typecheck` entries for these specs are removed from `docs/reports/suite_expectations.json` (109 -> 84, and the cap follows). The 52 seals of the changed specs were re-saved on the Railway t27c lab with zig on PATH.
- The gen-path typecheck gate itself (the other half of #6446) is hand-written Rust in `bootstrap/src/main.rs`. Under the 2026-10-05 t27-only PR rule it is held on branch `claude/t27c-gen-typecheck-gate` and is not in this PR.
