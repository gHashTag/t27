# NOW -- smoke-gate certified a theorem matrix it never generated (2026-08-21)

## fix(fpga): compute theorem_matrix_ok instead of hardcoding it true (Refs #2306)

- **The defect is live on `origin/master` verbatim.** `cli/tri/src/fpga.rs:6101` on `e058a03ea` is `let theorem_matrix_ok = true;`, consumed at `:6342` as `&& (!run_theorem_matrix || theorem_matrix_ok)`. Those were its only two mentions -- a verdict conjunct that no code path could ever set to `false`. #2306 reports its fixes as landed, but they went to a branch that never merged
- **It failed open, which is worse than the sibling it followed.** `dry_run_sweep_ok` (#2304, fixed in #2305) was declared `false` and never assigned, so it failed *closed* -- unpassable and loud. A hardcoded `true` is the inverse: `--theorem-matrix` reported the phase passed without executing a line of it, and `report["theorem_matrix"]` kept the `null` from its initializer while `passed` read `true`
- **The phase existed; only its call site was gone.** rustc had been saying so on every build: `generate_theorem_matrix`, `replay_theorem_matrix`, `build_theorem_matrix_report`, and the two properties they check, `pvt_context_inside_envelope` and `cclk_period_ns`, were all reported "never used". `tests/fixtures/fpga/smoke-gate/validate_lean_standalone_snapshot.json` still records the 24-variant block they used to emit. So this is the *compute it* case, not the *no such check exists* case
- **Fix**: `let mut theorem_matrix_ok = false;` plus the restored phase, in the shape `verify_lean_ok` uses twenty lines above -- set the flag and write the report entry inside the success path, record the phase as failed and `bail!` otherwise. `--replay-fixtures` and `--dry-run-live` are wired to `replay_theorem_matrix` and to the documented `dry_run_live` label / `theorem-matrix-dry-run-live/` directory; both were unused parameters, so `--replay-fixtures` had been silently regenerating rather than replaying
- **Two guards, two separate mutants**, because one mutant per file would leave the second guard unproven. Mutant A sabotages the underlying property (`pvt_context_inside_envelope` bound flipped to `> PVT_TEMP_MAX_C`): on master the gate still printed `[smoke-gate] complete (passed: true)` with `"theorem_matrix": null` and **exit 0** -- the defect, demonstrated -- and after the fix it exits 1 with `theorem-matrix generation failed: theorem-matrix envelope-check failed for corner ff OSCFSEL 0: synthetic PVT context is outside the operating envelope`. Mutant B walks two corners instead of three, which leaves every generated variant *valid* so it cannot trip guard A: master again exits 0 with `passed: true`, and after the fix `theorem-matrix verified 16 variants, expected 24`
- **Alive, not vacuous**: the phase writes 24 `.lean` files carrying 2 theorem declarations each, all verified through `verify_lean`, and the new test reads the files off disk rather than trusting the JSON block -- a report object alone is satisfiable by a literal
- **The existing suite could not have caught this.** `test_smoke_gate_json_synthetic_verify_lean` already passes `run_theorem_matrix = true` and asserts `passed == true`; the hardcoded flag satisfied exactly that assertion for free. The new test reads the `theorem_matrix` phase itself
- **Test isolation**: `smoke_gate()` derives its dry-run and fixture directories from the repo root, not from arguments, and deletes stale logs there on entry. Only one test reached those directories before, so the race had nothing to collide with; a second one made it fail on `remove ... boot-log-*.json: No such file or directory`. The four smoke-gate tests now take a mutex. No assertion was relaxed to accommodate it
- 168/168 `cargo test -p tri` pass; `cli/tri/src/fpga.rs` is `rustfmt`-clean
- Adjacent, **deliberately not fixed here**: item 2 of #2306, `validate_lean_standalone_ok` -- declared `false`, never assigned, no phase body. It fails *closed*, and both of its tests return early without `lake` on PATH, which is not available here or on the `cli-tri` runner. Writing a phase body that cannot be executed once, for a proof gate, is how an unproven guard lands. #2306 stays **open** on that item, which is why this is `Refs` and not `Closes`
