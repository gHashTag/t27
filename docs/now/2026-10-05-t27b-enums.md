# NOW -- t27b compiles plain enums as integer tags (2026-10-05)

## Plain enums: E.v, ==, !=, @intFromEnum, @enumFromInt, params, fields, locals (Closes #6146)

- t27b now accepts both enum forms: `enum E { .. }` and `const E = enum(T) { .. }`, with or without explicit values. The tag type follows t27c's Zig backend. With `enum(T)`, it is T. With no tag type and some explicit value, it is i32. Otherwise Zig picks the smallest unsigned type that holds every tag.
- A value lowers to its tag in one register, and to `size_of(T)` bytes in a struct field or constant. Names and literals work as values: `E.v`, `E::v`, and `.v` wherever an `E` is expected (args, returns, typed locals, fields, comparisons, `assert_eq`, `@as(E, .v)`).
- `==` and `!=` compare tags. Ordering is accepted only where t27c writes `@intFromEnum(a) < @intFromEnum(b)`, which means one side is `E.v`. On two enum values Zig has no `<`, so that is a clean reject.
- `@enumFromInt(x)` checks a runtime x against the tag range. An invalid value traps `invalid enum value` (TrapKind::EnumTag), as Zig's safety check does. A constant that is no tag is rejected, because Zig refuses it at compile time. Interpreter and JIT agree on every trap site.
- A runtime `@intFromEnum` of an auto-tagged enum (u2, say) is allowed in comparisons and where a wider integer is expected; anywhere else it is a clean reject.
- Clean rejects, each with its own construct name: methods `EnumDecl(method)`, `_` `EnumDecl(non-exhaustive)`, `union(enum)` `EnumDecl(union)`, `ExprSwitch`, a non-contiguous runtime `@enumFromInt`, and `.v` with no result type `ExprEnumValue`.
- `t27b corpus specs` (macOS arm64), before -> after: pass 162 (938 tests) -> 165 (973 tests); pass_vacuous 278 -> 278; fail 2 -> 2 (the same two files); rejected 763 -> 760; JIT/interpreter mismatch 0 -> 0.
- EnumDecl, the top first blocker in 109 files, no longer appears in the blocker list. Most of those files now stop on BenchBlock, f64, f32 or ?T.
- The three new passes are AsmSectionKind_from_i8.t27 (the reference passes it 8/8), HirBusPort_axi4_lite_slave.t27 (reference 23/23) and server/api.t27. The reference does not compile server/api.t27: an unused struct names the undeclared type MessageContent. Zig catches that eagerly; t27b lays out structs lazily.
- Reference (t27c Zig backend) bugs found on the way:
  - It drops the value of `const D: Dir = .east;` and emits `const D: Dir;`.
  - In a test block, it turns `var x = ..; x = f(x);` into a redeclaration `const x = f(x);`.
