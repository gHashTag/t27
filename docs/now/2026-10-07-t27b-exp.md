# NOW -- t27b: a run-time `@exp` calls compiler_rt's exp written in t27 (2026-10-07)

## `@exp` (Closes #7391)

- New module `specs/tri/t27b/libm.t27` (`T27bLibm`) carries Zig's compiler_rt `exp` and `expf` ported to t27, with 8 tests. The reference gives 8 pass, 0 vacuous; t27b gives the same 8.
- A run-time `@exp(x)` on `f64` or `f32` lowers to a call of that port. The fns are spliced in as a prelude under t27b's internal names `__t27b_libm_exp` / `__t27b_libm_expf`, so a file that declares its own `t27b_libm_*` fn (a mutant of libm.t27, say) cannot replace the one `@exp` calls.
- Zig folds a compile-time `@exp` with the compiler's own exp, which t27b does not reproduce bit for bit. `@exp` of a comptime operand, inside an invariant, or in a module constant stays refused as `ExprCall(@exp)`, and so does an integer operand.
- 8 mutants of libm.t27 each fail the same tests in t27b and in the reference. Of 16 probes, 8 pass in both, 2 fail in both, 1 (integer operand) is refused where the reference blocks, and 5 are honest t27b refusals of comptime `@exp` where the reference passes.
- Ledger: `gen_softmax.t27` moves to pass (5/5); `sigmoid_activation.t27` now stops at its next blocker; `libm.t27` is added as pass.
- Code is in `cli/t27b/src/lower.rs`, listed in `tools/policy/foreign-exceptions.txt` under the owner's approval on #6063. Lane 4 can reuse the same prelude path for `@log`.
