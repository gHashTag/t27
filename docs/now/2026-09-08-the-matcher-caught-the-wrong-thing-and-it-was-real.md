## The matcher caught the wrong thing, and it was real (Closes #3453)

- The parity table gained COMBINATIONS, and the round was not dry. Two forms are broken and both have a corpus population of **zero**: a tuple parameter reaches C as `probe((u8, i32) x)` -- the t27 text verbatim, though `c_tuple_info` already handles the RETURN position -- and `[]*i32` reaches it as `*i32* x`, `error: expected ')'`. Latent, and said to be.
- **The find of the pass came from a matcher that caught the wrong thing.** Written to count tuple parameters, it matched `Map(K, V)` instead, because a tuple and a generic application are both `Name(A, B)`. Generic structs: **28 specs, 33 types**, all under `specs/tri/`, and `t27c check` printed `Typecheck OK (0 errors, 0 warnings)` on every one while the generated C failed with `unknown type name 'K'`.
- Nothing noticed because the tolerance is deliberate: the parser records the type parameters and `collect_type_params` hands them to the unknown-type check so `K` and `V` are not reported as undeclared. Correct in itself, and it silences the only reader that might have said something about the rest.
- **The obvious message would have been false.** «No backend lowers generics» -- measured: `gen-rust` emits `pub struct Box<T>` and `pub fn get<T>(b: Box<T>)`, and it **compiles**. `gen-c` and `gen-zig` DROP the parameter from the declaration and KEEP it at every use, where it is undeclared. Verilog emits per-field regs. So the warning states the split, and a test compiles Rust's output to hold that half of the claim to account.
- My own two counts disagreed and only one was the population: a matcher over generated C prototypes said 8 files and 36 prototypes -- a different question, C prototypes carrying a **two**-parameter application -- and it cannot see a single `Option(T)`. The AST says 28 and 33. Measured over 651 specs: exit codes 573 / 78 before and after, **not one moved**. Three mutants, three dead, and the first was verified to be a COMPILE failure (`E0282`) rather than assumed to be a pass from an empty result.
- And the instruments now print their versions beside their counts. The same command gave 20 here and 50 on CI because one `cc` is Apple clang and the other gcc; a diagnostic count measures the code, the instrument and the machine, and only the first was ever written down.
