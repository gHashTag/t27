# NOW -- the spec explorer's compiler gets its source back (2026-09-21)

## A binary nobody could rebuild had stopped agreeing with the compiler, and the page was printing its answers (Closes #4487)

- **What was actually wrong.** `apps/website` ships a WebAssembly build of the bootstrap compiler so the spec explorer can lex, parse, typecheck and generate in the browser. Its driver said in a header comment that this is "the same code the CLI runs, not a reimplementation." **The source was committed in no repository** -- `git log --all -S"t27_analyze"` finds nothing here. The sync script's build step therefore fell through to the copy already vendored beside the corpus, silently, on every run since the file first appeared. A binary that cannot be rebuilt cannot be corrected, and this one had drifted.
- **How far it had drifted, measured rather than estimated.** Over the 1408-spec corpus the page ships: the old artifact produced an AST, a node count, a depth, a type verdict and five generated backends for **214 specs that `t27c parse` refuses**. Not sampled -- every one of the 214 was put to the CLI, and the CLI refused **214 of 214**. On 40 specs where both builds parse but the emitted Zig differs in size, `t27c gen` matched the new build **40 times and the old build 0**. The old artifact also traps on 2 specs where the new one does not.
- **So the page was not showing a spec's compile. It was showing a second compiler's opinion**, one that no test ran against and no CI job built. For 15% of the library that opinion was that a file the compiler rejects is fine.
- **The fix is the missing source, not a rewrite.** `bindings/wasm-explorer` reaches `bootstrap/src/{compiler,use_resolve,codegen_js}.rs` with `#[path]` rather than copying them, so there is exactly one copy of the compiler in the tree. `bootstrap/stage0/FROZEN_HASH` is **unchanged**: no freeze ceremony was needed, and none was performed.
- **The ABI is treated as a contract, because a browser can be holding yesterday's bundle.** `t27_alloc` / `t27_analyze` / `t27_free` keep their exact shapes and the JSON keeps its exact field names. `t27_analyze_named` is **added** beside `t27_analyze`, never in place of it, so that the JavaScript backend's header can name the real file and the reader can reproduce the output at the CLI.
- **The JavaScript layer, which is what this was started for.** `js` joins Zig, Verilog, Verilog (HIR), C and Rust on the layer strip, printing exactly what `t27c gen-js` prints (#4471).
- **A test that failed and was right to.** It asserted that master's `Lexer::dropped` records characters; it records **bytes**, so one em dash arrives as three entries -- `â` and two controls -- and the page's loss figure overcounts every non-ASCII character threefold. The vendored artifact did the same, so this is not a regression and not an improvement; it is the compiler's accounting. The test was rewritten to pin the behaviour **as it is**, because `compiler.rs` is sealed and the repair is a reseal, not a line in a browser binding. What the test buys is that the day it changes is visible here.
- **One list instead of six.** The five backend names were written out by hand in the layer strip, the stage bars, the metrics row, the sync script's labels, and three sentences that printed "of 5" as a literal digit. Adding a sixth backend made every one of them wrong at once. They now read `TARGET_IDS` from `t27Compiler.ts`, and `SpecExplorer.tsx` carries a type-level assertion that stops compiling if a backend is added with no layer to show it in. The sync script keeps its own copy -- node runs it directly and cannot import a `.ts` -- but it derives its count from that copy rather than from a digit, so the two can now disagree about a name and no longer about a number.
- **What this does NOT establish.** Nothing here says the 214 specs are fine, or broken. It says the page will now report them the way the compiler does. Which of them are damaged files and which are parser gaps is a separate question, and deliberately not answered on the way past.
