# NOW -- The Trinity compiler matrix as a .t27 spec (2026-09-12)

## S02 of gHashTag/trinity#988: the executable t27 subset and the compiler capability contract (Closes #3564)

- `specs/trinity/compiler_matrix.t27` (module `trinity_compiler_matrix`, `KIND = "compiler-matrix"`) names the native compiler (`t27c 0.2.0`; `NATIVE_REVISION` is the last commit that changed `bootstrap/`, `bff21b85`), the WASM the site vendors (built from `1cd2877f9`, its own column, no runtime), the four backends with the `t27c` command that emits each and what proves a runtime result on each (`cc -DT27_TEST_MAIN`, `zig test`, none for Rust, `t27c icarus-simulate` for Verilog), the four stages kept apart in every record (declaration, generate, compile, runtime), fourteen features of the Trinity headless profile with one fixture each under `bootstrap/tests/fixtures/trinity_matrix/`, five negatives with the latest stage at which each must be rejected, and an absent backend that must yield blocked.
- `tools/trinity_compiler_matrix.py run` carries every fixture through `t27c typecheck` and `parse --json`, then the four generators, the four host toolchains and the runners, and writes `conformance/trinity/compiler_matrix.json` with the revisions, the host tools, every stage per backend, the WASM column, and a verdict per feature: executable only when the fixture reaches a runtime pass on the backend the spec names. The declaration stage does what the compiler does not: it refuses a `pub const` whose literal disagrees with its annotation (`str = 5`), a `use` that resolves to no file, and a file whose top-level declaration count the parser did not consume. `check` holds the committed record to the spec and the fixture hashes; `--self-check` proves the good fixture executes and that a false assertion, a bad annotation, an unresolved import, a stale status, an accepted negative, a late rejection and a listed absent backend are each reported.
- Measured: 12 of 14 features execute on their backend (scalars, arrays, strings, structs, functions, control_flow, module_state, invariants, imports, errors, adapters_declared on C; clocked_state on Verilog through Icarus, 2 tests). `enums` is blocked on C: the enum declares `EVIDENCE_EMULATOR` and the switch compares against `EMULATOR`, so the C does not compile, while the same fixture executes on Zig. `ffi_boundary` is blocked at declaration: a bodyless signature is a parse error (gHashTag/t27#3472). The Rust backend emits declarations only for every fixture (`NOT LOWERED`), so no Rust runtime exists. The Zig backend (measured with the 0.17.0-dev nightly, because zig 0.15.2 cannot link a hello-world against the host SDK) runs 9 of 12 generated programs and does not compile string equality, array constants, invariant blocks or the clocked form. Verilog through Icarus runs 12 of 13 generated programs; the string fixture compiles and its three assertions fail in simulation.
- All five negatives are rejected: the invalid annotation and the unresolved import at declaration by this tool (the native `typecheck` and the vendored WASM both report `typecheck.ok` for them, and the C runner of the unresolved import even passes), the false assertion at runtime (the C runner aborts), the bodyless function and the dropped module by the parser. `typecheck.ok` alone is necessary, not sufficient, on both compilers.
- `tools/check_specs_generate.py` registers the fixture directory as control fixtures: the negatives exist to be rejected at a named stage and two positives are blocked on purpose, so a generate census cannot read their verdicts. `tools/published_figures.py`: the `test blocks` pin follows the corpus by the six test blocks of the spec, 12653 -> 12659; the fixtures are outside `specs/` and are not counted.
- Not claimed: that the 0.17 nightly is Trinity's supported Zig (build.zig needs 0.15.x, which does not link on this host); that any construct beyond the fourteen fixtures is executable; that the Rust or WASM columns carry runtime evidence; or that the compiler bugs recorded here are fixed -- gHashTag/t27#3472, #3004 and #3006 remain the issues that own them.
