- The lines: 20 `use std;`, 1 `use std.testing;`, and 12 that name no spec and no name the body reads (`use Constants;`, `use io::file;`, `use vsa::core;`, `use timestamp;`, ...). `specs/sandbox/orphan_detection.t27` also loses the two comment lines that described its two deleted imports. `use sandbox.session_timeout;` in `specs/sandbox/health.t27` stays, though the body reads none of its names: it names a spec that exists, so t27c resolves it and prints no witness (below). A resolved import that brings nothing is a later slice of #7191.
- The witness for each line is t27c's own zig output, not a text search. On master, `gen` printed `// use X: no references in this module` for 14 of them, and for 19 of the `use std;` lines it printed `const std = @import("std.zig");` beside the `const std = @import("std");` it adds by itself, so zig stopped at "duplicate struct member name 'std'". The 20th `use std;` (`specs/tri/crypto/base64.t27`) is one of the 14: its body names std only in parameter types, so the backend imports nothing and zig stops at "use of undeclared identifier 'std'", before and after (a compiler.rs matter, noted on #7191).
- A `use std;` is therefore not a harmless import of an implicit library, as it would be in Rust (where clippy calls it redundant): in t27 it breaks the zig build. The plan to exempt it from the #7176 warning is dropped.
