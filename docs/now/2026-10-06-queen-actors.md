# NOW -- BEAM-style actors under the Queen's agents, as a contract (2026-10-06)

## specs/queen/actors.t27 (Closes #6963, slice of #6657)

- `specs/queen/control.t27` gives the Queen events, fenced task leases and reusable domain agents. It does not say how one runtime addresses another, what a runtime receives first, what its death does to the others, or who brings it back. This spec takes those rules from the BEAM (Erlang/OTP) and adds no second lease, queue or registry.
- Identity: a pid is a slot plus a generation. A restart keeps the slot and takes the next generation, so anything addressed to the old pid reaches nobody. This is what control.t27's fence does for a lease.
- Mailbox: a send never blocks and is never acknowledged. A send to a dead pid is dropped. Order holds only per sender and receiver pair. Receive is selective: the oldest match, the rest stay in order, `after` bounds the wait and `after 0` polls. A packed u64 reference model with 8 slots lets every backend run the tests. Unlike the BEAM, the mailbox is bounded (256). A full one is a stuck runtime, and the reconciler repairs the dropped message.
- Links and exit signals: a trapping process gets an EXIT message. A non-trapping one ignores `normal` and dies of anything else. `kill` is untrappable, and its victim dies of `killed`, which a trapping neighbour survives. Linking to or monitoring a dead pid answers `noproc` at once. A monitor is one-way and yields one DOWN per monitor, and demonitor with flush drops a queued DOWN.
- Supervisors: permanent, transient and temporary children; one_for_one, one_for_all and rest_for_one. Temporary siblings are stopped and not restarted. A failure that is not restarted touches nobody. Children stop in reverse start order: SHUTDOWN, then KILL after the timeout. More than MaxR restarts in MaxT seconds make the supervisor give up with `shutdown`, and its parent decides.
- The Queen's tree: the root is one_for_one over the event intake, the reconciler and one permanent supervisor per domain. Agent runtimes are transient: a retired runtime stays down, and a crashed one restarts as a new pid, so it is a new lease holder. A DOWN from a lease holder reclaims its task at once. A DOWN with `noconnection` waits out the TTL. Intensities (3 in 300 s per domain, 2 in 900 s at the root) and shutdown times are chosen, not measured.
- Deliberately not the BEAM: bounded mailboxes, no hot code swap, no transparent distribution, no reductions scheduler, no global name registry.
- 16 tests and 6 invariants pass via `t27c gen` + `zig test`, and all six backends exit 0 deterministically. 62 of 62 mutants are killed. The first run killed 58 of 64: two survivors were dead lines, now removed (a push of tag 0 adds nothing; a restarting failed child is never temporary), and four were test gaps, now closed (a generation past 32 bits, a find for tag 0, rest_for_one restarting the failed child, an infinite shutdown at 2^32 - 1 ms).
- `t27c gen-js` lowers the constants and none of the function bodies, so the supervisor can import the numbers and must mirror the functions, as it does for control.t27.
- Not here: the wiring. The supervisor is TypeScript in gHashTag/BrowserOS. Its slice of #6657, BrowserOS#537, is still an open PR with leases, an event log and a heartbeat, and has no mailbox, link, monitor or restart.
