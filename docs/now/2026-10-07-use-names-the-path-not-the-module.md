# NOW -- a `use` names the spec's path, not its module name (2026-10-07)

## specs/ (13 files), .trinity/seals/ (26 files) (Refs #7191)

- t27c resolves `use a::b::Item;` by path: `specs/a/b.t27`. 24 import lines in 13 specs named a spec by the module name it declares instead (`bus-schema`, `lsp-schema`, `provider-schema`, `config-schema`, `sync-schema`, `runtime-process`), which is not a path, so nothing was spliced and the importer read undeclared names. Each now names the path (`bus::schema`, `lsp::schema`, `provider::schema`, `config::schema`, `sync::schema`, `runtime::process`); the six module declarations are in `specs/bus/schema.t27`, `specs/lsp/schema.t27`, `specs/provider/schema.t27`, `specs/config/schema.t27`, `specs/sync/schema.t27` and `specs/runtime/process.t27`. Rust and Go import by path the same way; a declared name is not an address.
- 8 `use tritype-base::usize;` lines are deleted: `tritype-base` is `specs/base/types.t27`, which declares no `usize`; `usize` is a builtin type.
- Measured on the Railway lab, 403b27f29 plus #7191's first slice against this change, all 1356 specs, `gen`, `gen-c`, `gen-rust` and `gen-verilog` under the #7176 build (PR #7242): the exit code changes on none of the 4 x 1356 runs; output changes only in the 13 edited files (gen 13, gen-c 9, gen-rust 9, gen-verilog 3). The #7176 warnings: 84 before, 52 after. Parse and typecheck failures: 0 before, 0 after.
- `t27c test-report`: all 13 are blocked before and after; none was passing. In 6 the first zig error moves from "use of undeclared identifier" (`Subscription`, `TextDocumentSyncKind`, `Diagnostic`, `ProviderType`, `Message`, `SyncID`) to `'_' used as an identifier without @"_" syntax`, which the specs' own `&.{ _ }` lowering now reaches. `specs/config/load.t27` moves from "use of undeclared identifier 'Config'" to the same error for `config_schema`: its body names 6 functions 22 times as `config_schema::...`, a qualified form this slice does not touch. The other 6 keep their error, one line earlier in 5 (the deleted `use tritype-base::usize;`) and on the same line in `specs/runtime/instance.t27`.
- `iverilog` diagnostics: `specs/config/load.t27` 9 -> 11 (a placeholder `0 /* PathsConfig {...} */` that elaborated silently is now a struct value iverilog rejects), `specs/provider/transform.t27` 21 -> 28, `specs/lsp/server.t27` 8 -> 8 (`input [31:0] range` becomes `[127:0]`). None of the 13 is in the elaboration ratchet (`tools/elab_baseline.txt`).
- Seals: the 13 resealed on the lab; 26 seal files change. `gen_hash_zig` changes on the 8 that lose `use tritype-base::usize;`, and no `gen_hash_c`, `gen_hash_rust` or `gen_hash_verilog` changes: a seal hashes the spec's own output, before any `use` is spliced. So the master binary and the #7176 build both print "all hashes MATCH" on all 13. What differs between them is the test record: `specs/lsp/client.t27` and `specs/lsp/server.t27` gain `tests.blocked`, written by the #7176 build, and this slice lands after #7242 so the record matches the binary that will check it.
