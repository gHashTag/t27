# NOW -- t27b corpus --reference-cache: whole rows, content-keyed (2026-10-05)

## Reference cache rows and key (Closes #6332)

- Each cache row is now formatted into one buffer (`cache_row`) and written with a single `write_all` to a file opened once in append mode, under one lock shared by every worker (`CacheWriter`). Before, `writeln!` on a per-row file handle could split a row into several writes, and one damaged line held two rows.
- The t27c part of the key is `binary_stamp`: FNV-1a over the binary's bytes, read once per run, instead of its size and mtime. A byte-identical copy of t27c (the lanes keep fixed copies) now hits the cache; a rebuilt binary misses. Old caches are still read; their rows simply never match.
- `cli/t27b/tests/refcache.rs`: 16 threads x 200 appends give 3200 well-formed rows, each path matching its key; a copy with a different mtime gives the same stamp; damaged and old rows are skipped harmlessly. Negative control: putting back the old `writeln!` append fails the concurrency test.
