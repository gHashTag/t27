# NOW -- t27b: `try std.testing.*` statements in tests lower like the reference (2026-10-05)

## try statements (Closes #6354)

- `cli/t27b` now lowers `try std.testing.expect(ok);`, `try std.testing.expectEqual(a, b);` and `try std.testing.expectApproxEqAbs(a, b, tol);` as statements in a test. A failed check fails only that test, and the following tests still run, the same as the error a test returns in the reference's Zig.
- `expectApproxEqAbs` follows Zig 0.16's `std.math.approxEqAbs`. A negative tolerance panics and fails the test. The check passes when `a == b` (so equal infinities pass) or when `|a - b| <= tol`, and a NaN always fails. Each operand is evaluated once, left to right.
- `try` in a bench, or in a fn nothing analyzed reaches, lowers to a stub trap, because the reference's Zig never analyzes those bodies.
- Every form the reference cannot compile is refused by name, and each was confirmed BLOCKED under `t27c test-report`:
  - `ExprUnary(try) in an invariant`: a container-level `comptime` block.
  - `ExprUnary(try) in a fn`: a non-error return type.
  - `ExprUnary(try) on a non-error call`.
  - `ExprCall(std.testing.expectApproxEqAbs) on comptime floats`.
  - `ExprCall(std.testing.expectApproxEqAbs) on a non-float`.
  - `ExprUnary(try) std.testing.<other>`.
