- Section 10 models a BEAM resource owner for a file. There is one owner per path key. Its slot is `file_owner_slot(path_hash)`, a section 1 pid above the Queen's tree. Two paths that share a slot only serialise more; they never admit an overlap. An edit names a region: the whole file, a line range of the base commit, or an append to a union-merged file. `edits_meet` says whether two edits collide. Touching ranges count as a collision, and an unknown kind or a bad range counts as the whole file. A boundary that names no range is the whole file, so a task that declares no range behaves as before.
- The scheduler calls `file_admit(meets_running, meets_queued, queue, waited_seconds)` instead of the binary skip. It returns FA_ADMIT 0, FA_QUEUE 1 or FA_REFUSE 2, and an invariant pins those codes. A queued edit keeps its place in the owner's queue, which is the section 2 model mailbox, MBOX_SLOTS deep. It takes no lane while it waits (`takes_a_lane`). An edit that waits past FILE_WAIT_MAX_SECONDS (7200 s, twice TURN_MAX_SECONDS) is refused, and `refusal_gives_up` counts that refusal against the issue. No person is waited for. A full queue refuses for this wake only, and that refusal is not counted.
