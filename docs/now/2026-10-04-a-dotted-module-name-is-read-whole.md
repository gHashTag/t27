## A dotted module name is read whole (Closes #5978)

- `module sandbox.health;` parsed as the module `sandbox` plus a stray top-level `StmtExpr` `.health` with line 0, and `use std.testing;` as the import `std` plus `.testing`. Twelve specs: eleven dotted module headers (`specs/sandbox/{health,https_enforce,modules,orphan_detection,session_timeout}.t27`, `specs/depin/prove.t27`, `specs/lsp/language.t27`, `specs/port/tools/check_graph_law8.t27`, `specs/port/trinity/src/tri/{gen_arithmetic,gen_image,gen_work_stealing}.t27`) and one dotted use (`specs/tri/io/compress.t27`). Found by the t27b corpus run; part of #5905.
- Parser: the module header keeps the dotted name verbatim (`sandbox.health`, `port::trinity.src.tri.gen_image`), the same string `extract_module_name` already gave the seal tool. A dotted use path is stored as the `::` path (`sandbox::session_timeout`, name `session_timeout`). A `.` counts only with an identifier after it; a later module header skips dots too. A `.` in a body is untouched.
- Every place the name becomes an identifier is sanitized: the C include guard (`SANDBOX_HEALTH_H`, was `SANDBOX_H`), the HIR Verilog module line and the gen-testbench DUT (`sandbox_health`). The AST Verilog path already sanitized; it now prints `module sandbox_health (` instead of `module sandbox (` and no longer emits `always @(*) begin health; session_timeout; session; end`, which is not Verilog.
- `use_resolve` splits a dotted use path like a `::` one, so `t27c gen specs/sandbox/health.t27` now pulls `Session`, `SessionStatus`, `Timestamp` from `session_timeout.t27`; it read `specs/sandbox.session_timeout.t27` before and pulled nothing.
- Zig: a use is no longer imported when its name is bound as a parameter or local. Named `session`, `use sandbox.session;` met the parameter `session` in `orphan_detection.t27` and emitted a `@import` the parameter shadows (6/6 Zig tests before, compile error after, 6/6 again with the guard). The guard also drops the same shadowed import from `specs/igla/coder/benchmark.t27` (`dataset`) and `compiler/cli/gen.t27` (`testgen`); both still fail `zig test` on unrelated undeclared identifiers, as before.
- Rust output is unchanged for every spec.
- Seals: generated-code hashes changed for 14 files across the tree (the 12 above, `benchmark.t27`, `compiler/cli/gen.t27`) and for nothing else among 1187 specs and 113 other `.t27` files. 20 seal files resealed with `t27c seal --save`, no `--force`; the four `specs/port` specs have no seal. `check_seal_currency.py`: 0 stale; `check_seal_coverage.py`: OK.
- Specs with a line-0 stray `StmtExpr`: 15 before, 3 after; the three left are unrelated (`automation/wrapup-auto`, `benchmarks/ternary_vs_binary`, `memory/notebooklm`). Parse failures 12 before, 12 after.
- `t27c suite --repo-root .`: TOTAL FAILURES 662 before and after, PRIMARY corpus 95 and 95, identical JSON summary (measured before rebasing onto current master; the seal checks were rerun after it).
- Tests: `bootstrap/tests/dotted_module_name.rs`, nine cases, including a field-access negative control and a qualified-call control for the import guard.
