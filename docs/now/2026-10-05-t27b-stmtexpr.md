# NOW -- t27b bench prose clauses lower to nothing (2026-10-05)

## Bench prose clauses in t27b, and scalar struct fields set from a call (Closes #6291)

- `t27b corpus specs --blockers` ranked `StmtExpr` first (+28 files). Read per file it is three shapes: 89 files a bench written as prose clauses (`measure: nanoseconds to f(x)`, `target: < 100ns`), 8 a statement at top level, 7 a stray `.b` from a dotted `module a.b;` (#6102). This change takes the first.
- The front-end keeps each prose clause as a childless StmtExpr named `<clause>:`; t27c's Zig backend writes `// NOT LOWERED: empty statement` for it inside a `bench_<name>` fn that nothing calls. t27b now lowers it to nothing inside a bench body and still rejects it anywhere else, so no test clause is dropped silently.
- Unblocking those files exposed two JIT/interpreter mismatches (gf16_dot4.t27, d6_test.t27): a scalar struct field initialised from a call (`Out{ .result = mul(a, b) }`) took the in-place path meant for an aggregate result and was never written. `Lower::init` now builds in place only for an aggregate type.
- Tests: differential `bench_prose_clauses_lower_to_nothing`; source `struct_field_initialised_from_a_scalar_call` (fails without the fix).
- `t27b corpus specs`: pass 223 -> 246, pass_vacuous 279 -> 279, fail 3 -> 4, rejected 711 -> 687, front-end error 40 -> 40, JIT/interpreter mismatch 0 -> 0. The new fail is gf16_dot4.t27 `intermediate_structure` (u16 overflow), which `t27c test-report` fails the same way.
- Of the 23 new passes, 20 pass under `t27c test-report` with the same test counts; apb_bridge.t27 and axi4.t27 do not compile on the reference path (CSE hoists `count + 1` above `var count`, #6292) and linker.t27 neither (`.align`, #4807), so they stay outside the honest denominator.
