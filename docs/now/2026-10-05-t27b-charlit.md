# NOW -- t27b: char literals, native, as comptime_int (2026-10-05)

## t27b char literals (Closes #6330)

- `'a'`, `'\n'`, `'\''` and the other escapes Zig accepts (`\n \r \t \\ \' \"`) lower to an untyped integer constant: t27c prints a char literal verbatim, Zig types it as comptime_int, and t27c's optimizer never folds or propagates one.
- Refused by name, because Zig rejects what t27c prints: `ExprLiteral(char escape)` (`'\0'`), `ExprLiteral(char byte)` (a raw control byte), `ExprBinary(char literal << >>)` (t27c prints `'a' << @intCast(k)`, a comptime_int shifted at run time).
- `t27b corpus specs --blockers --reference` against a t27c built from origin/master 634b3ff26: counted 601 -> 606 of 720, checked passes with tests 309 -> 314 (2033 -> 2067 tests), mismatch 0 before and after.
- Seen, not fixed here: t27c drops the value of a module-level `const X: u8 = 'a';` (gen prints `const X: u8;`), and prints a char switch arm as `.'a'`.
