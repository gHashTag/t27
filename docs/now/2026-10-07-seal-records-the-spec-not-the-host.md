# NOW -- a seal's test record names neither zig's temp directory nor a missing zig (2026-10-07)

## bootstrap/src/test_report.rs, bootstrap/src/main.rs, bootstrap/tests/seal_reseal_is_stable.rs, bootstrap/tests/seal_built_by.rs, bootstrap/tests/seal_refuses_failing_tests.rs (Refs #7243)

- The defect: `seal --save` wrote two facts about the sealing host into the spec's test record. zig ran on absolute paths in `t27c-test-report-<stem>-<pid>`, and it prints a path the way it was given, so a blocked record read `does not compile: /tmp/t27c-test-report-base64-1901717/spec.zig:...`: two reseals of one spec with one binary wrote two different files (512 seals on master carry such a path). And with no zig on PATH, `seal --save` exited 0 and wrote `"blocked": "zig not on PATH"` over the spec's last measured result.
- The fix: zig now runs from its working directory and is given the file names alone, so the line reads `does not compile: spec.zig:18:56: error: ...` in `test-report` and in the seal. t27b already cut the same prefix off (`cli/t27b/src/blockers.rs`), so its comparisons see the same text as before. A report blocked by a missing zig is a new verdict, `Unmeasured`: `seal --save` refuses it with exit 1 and says why; `--force` still writes it, as it writes failing tests.
- Measured on the Railway lab, the 403b27f29 tree (no bootstrap change since), each spec resealed twice in a row with the same binary: with master's t27c, `specs/tri/crypto/base64.t27` (blocked) differs in 2 lines besides `sealed_at` and `specs/sandbox/orphan_detection.t27` (6 of 6 pass) in 0; with this change both differ in 0. `PATH=/usr/bin:/bin t27c seal --save specs/sandbox/orphan_detection.t27`: master exits 0 and seals "zig not on PATH"; this change exits 1 and writes nothing. `test-report` on the two specs took 856 ms on master and 872 ms here.
- Tests: `a_compile_error_names_the_file_not_the_work_dir` and `a_missing_zig_is_not_sealed_without_force` in `test_report`; `tests/seal_reseal_is_stable.rs` reseals a blocked and a passing probe twice and compares the files without `sealed_at`, and runs `seal --save` with an empty directory as PATH. Negative controls on the lab: `build()` put back as on master turns `a_compile_error_names_the_file_not_the_work_dir` and `a_blocked_reseal_changes_only_sealed_at` red; the `Unmeasured` return removed turns `a_missing_zig_is_not_sealed_without_force` and `no_zig_is_refused_unless_forced` red. `seal_built_by` passes `--force` when zig is absent, so it still runs on such a host (it passed with and without zig on PATH).
- `seal_refuses_failing_tests::a_blocked_spec_is_sealed_with_a_notice` still pinned the old no-zig behaviour, and the first full `cargo test --release -p t27c` on the lab (merged with 80cbb0cff) failed on it. The targeted runs above had not included it. It now asserts exit 1, the reason named and no file written, then seals with `--force` and keeps its old checks. On the lab it passes 4 of 4, and `seal_reseal_is_stable` 3 of 3. In the same full run `zig_primitive_bindings` failed 1 test, then 3 on a rerun, each "failed with SystemResources" when zig spawned (lab pids 705 of 1000, zombies with PPID 1, #7090). It runs neither seal nor test-report.
- The 512 recorded paths go away as each spec is next resealed; no bulk reseal is part of this change.
- Foreign Rust under the standing owner rule (label owner-approved-foreign): `test_report.rs`, `main.rs` and `seal_built_by.rs` are already listed in `tools/policy/foreign-exceptions.txt`; the new test and `seal_refuses_failing_tests.rs` are added there. `bootstrap/src/compiler.rs` and FROZEN_HASH are not touched.
