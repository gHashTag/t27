# NOW -- t27b: switch expressions and negative const literals lower like the reference (2026-10-05)

## switch, negative literals, dropped call results (Closes #6352)

- `cli/t27b` now lowers a `switch` expression on an enum or an integer operand as a lazy chain of selects, so only the taken prong runs (#6328). The operand is evaluated once, and a const operand lowers only its prong.
- A `const X: i32 = -1;` literal, which the t27c parser folds into one token and its Zig backend prints back as written, now lowers as a comptime int instead of being refused.
- Every switch shape the reference cannot compile is refused by name, each confirmed BLOCKED under `t27c test-report`: `ExprSwitch(not exhaustive)`, `(unreachable else)`, `(duplicate prong)`, `(prong)` and `(char prong)` (#6329).
- New refusal `ExprCall(value ignored) statement`: `f(x);` with a non-void `f`, where `zig test` analyzes the body. It is the reason `specs/fpga/bpsk.t27` is BLOCKED in the reference; without it t27b passed that file once its negative literals lowered.
- Benches are no longer analysis roots. t27c emits a bench as an uncalled `fn bench_<name>() void`, so neither its body nor a fn only it names is analyzed by Zig.
- `t27b corpus specs --blockers --reference t27c` at master f25dbeee8: counted pass 623 -> 629 of 720, checked pass 346 -> 352, rejected 569 -> 564, mismatch 0 -> 0, no file regressed.
- New tests in `cli/t27b/tests/source.rs`: `switch_runs_only_the_taken_prong` and `discarded_call_result_is_refused_where_reached`. Their verdicts equal `t27c test-report` on the same sources.
