## The spelling that looked right checked nothing (Closes #3434)

- `gen-c` lowered `[4]u8` to `uint8_t*`, so a caller passing a two-element array compiled in silence. `gen-rust` keeps `[u8; 4]` and Zig keeps `[4]u8`; C was the one backend that dropped the length.
- The obvious repair is wrong, and only a measurement says so. Apple clang 21 with `-Wall -Wextra`, a 2-element array into a 4-element parameter: `void f(uint64_t a[4])` is SILENT -- the parameter decays to a pointer -- while `void f(uint64_t a[static 4])` reports `array argument is too small; contains 2 elements, callee requires at least 4`. A test asserting only on the emitted text would pass on the spelling that checks nothing, so the regression test hands both a short caller and a correct one to `cc` and requires the diagnostic on the first and its absence on the second. Mutating `[static {}]` to `[{}]` kills it.
- Population is the emitter's own count, not a grep: **51 parameters in 24 functions across 12 files**. Two earlier figures are withdrawn -- "fiat-crypto's `uint64_t out1[4]` cannot be passed short without a diagnostic" is false, and "150 parameters across 120 functions" came from a line-based regex that cannot see a multi-line parameter list.
- Corpus parity, old binary against new, 582 translation units each: 881 distinct diagnostic kinds with every count identical, 3849 errors and 2705 warnings on both sides, and all 48 changed lines contain `[static `. The comparator was checked against a planted short call inside the real generated corpus, which it reported -- so the parity is a measurement and not a blind spot.
- It finds no existing defect: the corpus compiles to 0 `-Warray-bounds` today. It is a guard for the next caller. Narrowed to parameter position, because `param_type_to_c` also spells struct fields where `[static N]` is a syntax error, and refused for `[static 0]`, which is not valid C.
