# NOW -- t27b: an `if` used as a value, native, only the taken arm runs (2026-10-05)

## t27b ExprIf (Closes #6327)

- New IR node `Select { cond, then, els }`, lowered as a branch (not a `csel`): a trap or a call in the arm not taken never runs, as in Zig. Interpreter, AArch64 codegen and the differential fuzzer all know it.
- Arms take the result type (a return, a typed binding, a parameter) or their peer type; string and struct arms select an address; a condition known at compile time lowers only its arm.
- Refused by name: `ExprIf(no else)`; `ExprIf(comptime arms)` (Zig cannot type two comptime_int arms behind a runtime condition); `ExprIf(left operand)`, because t27c prints `(if (c) a else b) + 1` as `if (c) a else b + 1` and Zig reads the `+ 1` into the else arm.
- `t27b corpus specs --blockers --reference` against a t27c built from origin/master: counted 597 -> 601 of 720, checked passes 326 -> 329 (2020 -> 2033 tests), mismatch 0 before and after.
- Seen, not fixed here: t27c prints `-(x - y)` as `-x - y`.
