# NOW -- t27c names each `use` it splices nothing from (2026-10-07)

## bootstrap/src/use_resolve.rs, bootstrap/src/main.rs, bootstrap/tests/unresolved_use.rs (Refs #7176)

- The defect: t27c resolves `use a::b;` by walking up from the input file to a `specs/` directory and splicing `specs/a/b.t27`. A `use` whose file does not exist was skipped without a word, and `gen` exited 0. The first sign was a later error about a name the import would have brought, in another tool's output (#7148 met it as zig's "use of undeclared identifier 'LIST_END'" in a temp-dir copy).
- Each gen command now prints one stderr line per such `use`, with the file, the line and the reason: `warning: <file>:<line>: use <path> resolves to no spec: <why>; nothing is spliced from it (#7176)`. The reasons it names: no spec at the path; no `specs/` directory above the file; a brace list (`use a::{X, Y};`, not read, #2537); one item of a module whose file exists (`use a::b::Item;`, not read, #5552).
- The note is printed once, from `typecheck_gate`, which each of the 10 gen paths calls once (gen, gen-verilog, gen-verilog-for-simulation, gen-verilog-hir, icarus-simulate, icarus-cocotb, gen-testbench, gen-c, gen-rust, and the shared AST path of gen-js/gen-ts). It reads the `use` line the way the splice reads it: the splice and the note share `use_path_expr` and `use_path`, so they cannot disagree about which line is an import or where its file is.
- A warning, not an error, for two measured reasons. First, the tracked corpus has 182 such lines: 112 name no spec at all, 54 name one item of a module (#5552), 16 are brace lists (#2537), 0 sit outside a `specs/` tree. An error would fail 106 files today. Second, a qualified reference through a `use` still makes the zig backend emit `@import("x.zig")` with no spec to splice, and `tests/dotted_module_name.rs` relies on that `gen` succeeding in a temp dir. The error is the next step of #7176, after #5552 and #2537 are read.
- Measured on the Railway lab, master 403b27f29 against this branch, both release builds, `gen` on each of the 1484 tracked `.t27` files: stdout differs on 0, the exit code on 0, stderr other than the new lines on 0. The new lines number 182 in 106 files, the same 112 / 54 / 16 / 0 a separate census of the corpus's `use` lines printed before the change.
- Tests: 5 unit tests in `use_resolve::missing_use_tests` (each `use` line is either spliced or named, never both and never neither; the line numbers; the exact text; each reason; the no-`specs/` case) and 2 CLI tests in `tests/unresolved_use.rs` (a missing target is named with its line and `gen` still exits 0; a found target prints nothing and is spliced). Negative controls on the lab: the `typecheck_gate` loop removed turns the CLI test red; `missing_uses` returning nothing turns the unit tests red.
- Foreign Rust: `bootstrap/src/use_resolve.rs` and `bootstrap/tests/unresolved_use.rs` are listed in `tools/policy/foreign-exceptions.txt` (standing owner rule, label owner-approved-foreign); `bootstrap/src/main.rs` already was. `bootstrap/src/compiler.rs` and FROZEN_HASH are not touched.
