# NOW -- t27c names each `use` it splices nothing from, and reads item and brace imports (2026-10-07)

## bootstrap/src/use_resolve.rs, bootstrap/src/main.rs, bootstrap/tests/unresolved_use.rs, specs/neural/forward_pass.t27 (Refs #7176)

- The defect: t27c resolves `use a::b;` by walking up from the input file to a `specs/` directory and splicing `specs/a/b.t27`. A `use` whose file does not exist was skipped without a word, and `gen` exited 0. The first sign was a later error about a name the import would have brought, in another tool's output (#7148 met it as zig's "use of undeclared identifier 'LIST_END'" in a temp-dir copy).
- Commit 1: each gen command prints one stderr line per such `use`, with the file, the line and the reason: `warning: <file>:<line>: use <path> resolves to no spec: <why>; nothing is spliced from it (#7176)`. It is printed once, from `typecheck_gate`, which each of the 10 gen paths calls once. The note and the splice share `use_path_expr` and `use_path`, so they cannot disagree about which line is an import or where its file is. Measured on the Railway lab, master 403b27f29 against commit 1, `gen` on each of the 1484 tracked `.t27` files: stdout differs on 0, the exit code on 0, stderr other than the new lines on 0. 182 lines in 106 files: 112 named no spec, 54 named one item of a module whose file exists (#5552), 16 were brace lists (#2537).
- Commit 2: the two item forms now name the module that holds the items, as in Rust. `use a::b::{X, Y};` and `use a::b::Item;` (when `specs/a/b/Item.t27` is not a spec) splice from `specs/a/b.t27`, one level up only. The module's basename is not a qualifier after an item import (`b::K` is not rewritten, as `b` is not in scope in Rust either). The warnings drop from 182 to 119, in 70 files: each names neither a spec nor a module to take an item from (7 of them brace lists).
- Tried and reverted: Rust's rule that an explicit item outranks a glob, to settle a name two imported modules declare. On `specs/base/ring_32.t27` it picked math/sacred_physics' `TRINITY`, whose closure declares `PHI` as `constants::PHI`. The splice rewrites qualifiers only in the importer, so zig failed on `constants` where the unspliced output passed its test (#7215). A listed name two modules declare stays `UNRESOLVED`, as with whole-module imports. rustc (E0432), zig, Go and TypeScript (TS2307) all make an unresolved import a hard error; this stays a warning until the 119 are gone.
- Found by the A/B, three defects of the splice older than this change, each one now made visible by a module the item imports splice:
  - It took the smallest indent of any declaration as the module's own. In `specs/fpga/testbench/spi_tb.t27` (a body at four spaces, one `fn` at column 0) every name in the body read as not local, and the splice pulled a second `spi_transfer` beside the spec's own: zig "duplicate struct member name". Names the importer declares at module level are now found by brace depth (depth 0, or 1 inside `module M {`), and none of them is pulled. The same change dropped a duplicated `DifferentialCase` from `specs/test_framework/property_test_template.t27`'s output.
  - A declaration ended at the first line where the `{}` and `[]` depth was back to 0, so a header split over lines (`fn f(` ... `) -> T {`) was its first line alone. `mac_tb` got `fn mac_parallel_multiply(` glued to `mac_reset`'s body, and zig stopped at "expected ')', found ':'". The `()` depth now counts too. On master the same cut made `specs/nn/hslm.t27`'s splice fail to parse, and t27c fell back to the unspliced source with a note; that note is gone.
  - The scan read a char literal `'"'` as the start of a string and hid the rest of its line. With the `()` depth that hid a `)` in `specs/policy/own_language.t27`, its declaration never closed, and the first lab run of the fix dropped `verdict`, `put` and `put_msg` from the output of `ci/affected` and `policy/l2_generation`. Char literals and `;` prose lines are now read as such; that run is why the tracked gen/ copies are checked below.
- `specs/neural/forward_pass.t27` passed a trailing `dim`/`1024` to six `vsa_core` functions that take none. Once its brace import spliced them, `gen` exited 1 on the arity. The 42 call lines now match `vsa_core`, and its two seals are resealed (still "blocked: does not compile", as before). No other seal moves: `compute_seal_hashes` hashes the unspliced source (#7203).
- Measured on the lab, commit 1 against commit 2, both release builds, gen/gen-c/gen-rust/gen-verilog on each of the 1484 files: the exit code changes on 0; output changes on 17 specs (gen 17, gen-c 17, gen-rust 17, gen-verilog 1: mac_tb); stderr other than the #7176 lines changes on 4 (ring_32, bridge and mac_tb gain `UNRESOLVED` notes, hslm loses its fall-back note). `zig test` (0.16.0) on the 17 changed `gen` outputs: 3 pass under both binaries, 14 fail under both, none goes from pass to fail. Four of the 14 fail further on (bridge, mac_tb, power_analysis_tb, hslm): the imported names arrive and the next error is a name two modules declare, or a defect in the spec or its module. The 15 tracked gen/ copies: 13 are byte-identical to both binaries' output; the 2 gf16 copies differ from both, as before (#6996).
- Tests: 38 unit tests in `use_resolve` (32 before), 8 of them in `missing_use_tests`; 2 CLI tests in `tests/unresolved_use.rs`; `tests/dotted_module_name.rs` 9 of 9. Negative controls on the lab, each a hand-made regression that turns named tests red: the `typecheck_gate` loop removed (the CLI test); `missing_uses` returning nothing (the unit tests); the brace-depth names left out of the local set (`a_name_the_importer_declares_in_a_nested_body_is_not_pulled`); the `()` depth left out of the end test (`split_decls_keeps_a_header_split_over_lines_with_its_body`); char literals read as text (`depth_change_skips_char_literals_strings_and_prose`, `split_decls_ends_a_body_whose_line_holds_a_quote_char`).
- Foreign Rust: `bootstrap/src/use_resolve.rs` and `bootstrap/tests/unresolved_use.rs` are listed in `tools/policy/foreign-exceptions.txt` (standing owner rule, label owner-approved-foreign); `bootstrap/src/main.rs` already was. `bootstrap/src/compiler.rs` and FROZEN_HASH are not touched.
