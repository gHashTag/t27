# NOW -- t27b compiles bench blocks and never runs them, as the reference does (2026-10-05)

## Bench blocks: compiled, not run, not counted (Closes #6179)

- The reference path (`t27c gen` + `zig test`) emits a bench as a plain `fn bench_<name>() void { ... }` that nothing calls. `zig test` does not run it and does not count it. Zig analyzes such a fn lazily, so it does not even type-check the body: a `const bogus: u8 = "not a u8";` placed in the bench of numeric/e8m0 still gives "All 18 tests passed", and adding one `_ = &bench_e8m0_decode_encode;` turns it into a compile error.
- t27b now lowers each bench body with the test binding rule (the rule t27c's `gen_bench_block` uses), compiles it to AArch64, and then drops it. It is never run and never counted as a test. A failing assert inside a bench does not fail the file, as in the reference.
- No body is skipped without a word. A body t27b cannot lower rejects the file under the construct it contains (for example `StmtFor(range)`), never under `BenchBlock`. A body the code generator refuses rejects the file as well. This is stricter than Zig, which never looks at the body.
- `t27b corpus specs` (macOS arm64), before -> after: pass 165 (973 tests) -> 169 (1024 tests); pass_vacuous 278 -> 278; fail 2 -> 2 (the same two files); rejected 760 -> 756; JIT/interpreter mismatch 0 -> 0.
- BenchBlock, the top first blocker in 116 files, no longer appears in the blocker list. Of those 116 files, 4 now pass, and the reference agrees on all four with the same test counts: boards/wukong_v1 15/15, igla/race/ternary_lut_table 15/15, numeric/e8m0 18/18, numeric/golden_sieve 3/3. The other 112 now stop on a real construct. The commonest are StmtAssign(undeclared) 23, StmtExpr 22, ExprLiteral(negative literal) 19 and ExprCall(method) 7.
- In 22 files the stop is StmtExpr "empty statement". Those benches use the prose form `measure: nanoseconds to ...` / `target: < 100ns`. The t27c front-end lowers that form to nothing, and its Zig output says so in a `// NOT LOWERED: empty statement` comment. t27b rejects such a body instead of passing an empty one.
- New top first blockers: type f64 110, type f32 70, type ?T 47, type std.mem.Allocator 44, type [N]T 39.
- The reference never compiles bench bodies, so a broken one goes unnoticed. Of the 116 files, 37 pass `zig test`, 78 fail it, and one (fpga/testbench/gf16_accel_tb) hangs in a test. In 8 of those 37, adding `_ = &bench_x;` to a test makes Zig reject the bench body. Seven are fpga board and testbench specs ("value of type 'u32' ignored"); the eighth is isa/ternary_gates ("unable to resolve comptime value"). t27b rejects all 8 files anyway, on other constructs earlier in the file.
