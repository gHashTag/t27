# NOW -- t27b computes f64 in AArch64 FP registers (2026-10-05)

## f64 arithmetic, compares, conversions and AAPCS64 d0-d7 in t27b (Closes #6180)

- t27b now compiles f64 `+ - * /`, unary minus, the six comparisons, float literals, f64 params, results, locals and consts. Arithmetic runs in d16/d17 (FADD, FSUB, FMUL, FDIV, FNEG, FCMP); a value lives as its bit pattern in an X register or slot.
- `@floatFromInt` and `@intFromFloat` in Zig spelling take the result type from context (SCVTF/UCVTF, FCVTZS/FCVTZU). Out of range and the infinities trap at a named site; a NaN gives 0, which is what Zig 0.16 Debug does (checked with `zig test`).
- AAPCS64: f64 arguments and results go in d0-d7 (`jit.rs` marshals them, `call_fp`).
- Compile-time floats follow Zig's f128 comptime_float: only literals that are exactly a double are folded; inexact ones may only be coerced to f64. `@sqrt` and `std.math.*` stay rejected and `--blockers` names them (`ExprCall(@sqrt)`). No f32, no interpreter fallback.
- FR-002: encoder tests cite the ARM ARM for every new instruction (151 cases). FR-003: eval computes f64 the same way; five `f64_` differential tests compare interpreter and JIT bit-for-bit, a disagreement fails.
- Corpus `t27b corpus specs`: pass 166 -> 181 (1024 -> 1124 tests), pass_vacuous 278 -> 279, fail 2 -> 3, rejected 762 -> 745, mismatch 0 -> 0. The 16 newly passing files pass under `t27c gen` + `zig test` too; the new fail (gen_vector2d.t27 Vec2_length) fails under zig as well.
- Found in t27c: `strength_reduce` turns f64 `x * 2` into `x << 1` (#6284); t27b refuses that shape as `ExprBinary(f64 * 2^k)` until it is fixed.
