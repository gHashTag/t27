# NOW -- Trinity Memory contracts as .t27 specs (2026-09-11)

## Trinity Memory contracts as .t27 specs (Closes #3561)

- `specs/memory/tmem/` adds six sealed specs from `dmitrii-f-t27/trinity-memory` (v0.3.0, epic #3 there): `types.t27` (module `TrinityMemoryTypes`: lanes, codec ids and geometry, code limits, the TMEM v1 container, CRC32, the `TMS_ERR_*` codes, the `Evidence` enum), `bridge.t27` (JSON-RPC 2.0 over loopback HTTP: methods, error codes, HTTP rejections, request limits, handles, identity, the anchor word), `tensorpack.t27` (TTPK v1: 32-byte header, sorted-key metadata, limits, float presentation), `stream_compute.t27` (read -> decode -> dot: two-stage ready/valid pipeline, accumulator bounds, frame errors, storage sequencer timing, view packing), `conformance.t27` (fixture schema `trinity.conformance.v1`, plan counts, corruption positions, lab report sections) and `edge_demo.t27` (3x12 template classifier, argmax with ambiguous ties, seeds, report `trinity.edge-report.v1`). `specs/memory/tmem/OWNERS.md` records the conventions and the pinned-compiler pitfalls the files avoid.
- The files are byte-identical to the memory repository's `specs/memory/*.t27` except for the path line in each header. Seals `.trinity/seals/tmem_TrinityMemory*.json` were produced by `t27c seal --save` at `bff21b85` (this repository's `master`) from the `specs/memory/tmem/` paths; `t27c ci --repo-root .` reports the six files with no issue and `t27c validate-conformance --repo-root .` accepts the six vector files `conformance/tmem_*.json`.
- Every constant, layout and cycle-level rule in the specs is checked against the implementation in the memory repository: differential C harnesses over the generated headers (`tests/native_spec_*.c`), Icarus trace testbenches over the generated Verilog (`tests/tb_spec_dot_trace.v`, `tests/tb_spec_storage_trace.v`), replays over TCP and WASM, and the vector generator `tools/generate-spec-vectors.py --check`. All of that runs there under `tools/check-specs.sh`; none of it is copied here.
- 51 `test` blocks with asserts inside the six specs; every `invariant` is a constant expression (the pinned compiler emits a non-constant invariant as a comment, and folds an `assert` whose expression begins with `(` into a call -- both recorded in the OWNERS file).
- `tools/published_figures.py`: the pinned `test blocks` population follows the corpus, 12542 -> 12593 (the 51 test blocks of these specs), with the movement written next to the pin as the file's protocol asks; the other nine figures are unchanged and `--check` exits 0.
- Not claimed: the memory protocol and TTPK are experimental contracts of the memory repository, not an approved ABI of `trinity-node` or `trinity-sdk` (the Bridge spec pins the revisions it was checked against); no FPGA number, no existing spec, seal, conformance file or generated file is touched.
