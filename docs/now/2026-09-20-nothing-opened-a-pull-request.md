# NOW -- Twenty bees, three days, nothing shipped (2026-09-20)

## A publisher, because nothing in this system opened a pull request (Closes #4321)

- **401 `queen-*` branches on the remote; the last bee pull request was opened on 2026-09-17.** Seventeen pull requests merged in the last twenty-four hours and not one of them came from a bee. Of the forty most recent branches, 24 carry real commits, 9 carry only a salvage commit, 7 are empty -- and all 24 were invisible.
- Nothing opens a pull request. The Queen skips issues that ARE pull requests and never creates one; the container holds no push credential by design; the job that used to do it was a person running a script on a laptop. So every instrument reported a healthy swarm at ninety percent utilisation, because every instrument measured DISPATCH and none measured DELIVERY.
- `tools/queen/publish.py` opens them, at most five per run, twice an hour. Five is not timidity: each pull request starts twenty-odd workflow runs, and this repository has already had a CI queue of 1073 superseded runs starve its own gates.
- It adds the one thing the bee cannot: a `docs/now/` entry, with `Closes #N` in the commit message because L1 TRACEABILITY reads commit messages and not pull request bodies. The entry says the publisher wrote it and does not pretend a bee did.
- What it REFUSES, each for a measured reason: a branch that already has a pull request; no commits; no diff; a closed issue; files outside the issue's `## Boundary`; a branch that conflicts with master (GitHub runs no required check on a branch it cannot merge, so it reports as waiting for CI forever -- thirteen such were closed by hand on 2026-09-19); and anything too large to be one turn, because `queen-3678` sits 3269 commits ahead of master.
- Proven before it was shipped: a probe published by hand, #4317 (`queen-4286`, a restored `swap()` and a test), needed exactly one thing -- that entry -- and failed L1 until the commit said `Closes`. A dry run then read: 6 would publish, 1 conflicts, 1 too large, 8 have closed issues, 2 have no commits, 1 already has a pull request.
- Ledgers moved in this same commit, both of them: `queen-publish.yml` is classified in `check_pr_branch_filters.py` (the count stays at the ceiling of 24, which is the point of a ceiling that only moves down), and the census reads `quiet` 58 -> 59 workflow files and 137 -> 139 "named a path but not quiet"; `shell` 58 -> 59 files, 79 -> 80 jobs, 269 -> 272 run-steps, 248 -> 251 run with `bash -eo pipefail`.
- What this does NOT establish: that the work is good. The gates on each pull request judge that, and they are the same gates every other change meets.
