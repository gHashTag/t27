# NOW -- t27b: tuples lower like the reference (2026-10-05)

## tuples (Closes #6450)

- `cli/t27b` now lowers tuples the way the reference's Zig does. That covers:
  - a tuple type in a fn return type, positional `(u32, u32)` or named `(lo: u32, hi: u32)`;
  - `return (a, b)`;
  - `let` / `var (a, b) = ..`, where a named tuple is read only from a direct call;
  - the top-of-test `(a, b) = f()` form;
  - `t.0` and a comptime `t[0]`;
  - a struct inside a tuple, and forwarding a tuple return;
  - `.{ .. }` into an array.
- The code lives in the new submodule `cli/t27b/src/lower/tuple.rs`, with small hooks in `lower.rs`. It is hand-written Rust: 335 lines of debt under the port epic #6198, to be replaced by a `lower/tuple` slice of the t27b-in-t27 specs.
- Every form the reference cannot compile is refused by name, and each was confirmed BLOCKED under `t27c test-report`:
  - `type (tuple)`: a tuple type in a param or a local annotation.
  - `StmtAssign(tuple)`: `(a, b) = ..` in a fn body, which Zig refuses as `.{ a, b } = ..`.
  - `ExprTuple`: a count mismatch.
  - `StmtLocal(destructure)`: a count mismatch.
  - `ExprIndex(tuple)`: a runtime index, or one out of bounds.
  - `ExprFieldAccess`: `q.0.x`.
- The untyped tuple local `const t = (v, 2)` stays refused as `ExprTuple`.
- `t27b corpus specs` at master f6336acac, against the lab's reference verdicts at 03362c1da:
  - counted pass 660 -> 668 of 722.
  - mismatch 0 -> 0, the same 8 fails as the lab, and no file regressed.
  - Files that now pass: sensitivity, temporal_heartbeat, link_node, install-constitutional-hook, tools/oracle/run, d_simple_ff, d_slow_blink, d_y0_test.
- New tests in `cli/t27b/tests/source.rs`: `tuples_as_the_reference_lowers_them` and `tuples_rejections`. Their verdicts equal `t27c test-report` on the same sources.
- Reference bug filed: #6447. Const-inlining reads a var after it was reassigned, so a swap computes the wrong value.
