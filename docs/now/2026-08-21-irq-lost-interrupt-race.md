# interrupt_controller discarded every interrupt coincident with a status read

- Confirmed the defect is live on `master`, verbatim, at `bootstrap/src/bitnet_irq.rs:100-103`: the emitter writes three per-bit latches and the whole-register read-to-clear as **four separate non-blocking assignments inside one `always` block**. Verilog resolves those last-write-wins, so the clear beats the source and the event is dropped — on every reachable state, not intermittently. A host servicing the IRQ silently loses any event arriving in the same cycle as its status read.
- Reproduced in simulation **before** changing anything, on the module emitted straight out of master's emitter (`iverilog` + `vvp`): asserting `inference_done` in the same cycle as `status_read` leaves `irq_status = 000`. The fixed emitter leaves `irq_status = 001`. The same testbench also checks read-to-clear, stickiness across cycles, and the `irq_enable` mask — all three pass on both versions, so the fix does not trade one behaviour for another.
- The fix is one assignment: `irq_status <= (status_read ? 3'b000 : irq_status) | {error, dma_done, inference_done};`. The clear applies to the *previous* value and this cycle's sources are ORed on top. Bit order `[2]=error, [1]=dma_done, [0]=inference_done` is unchanged. Elaborates under yosys to `$adff` + `$mux` + `$or` with no inferred latch and no combinational feedback.
- **Two tests had pinned the bug in place.** `each_source_latches_its_bit` and `status_read_clears_latch` — in both `bootstrap/src/bitnet_irq.rs` and `bootstrap/tests/bitnet_irq.rs` — asserted the literal text of the buggy chain. They passed for exactly as long as the race existed and would have failed the moment anyone fixed it: the wrong way round. Both now assert the merged assignment and the bit map it encodes.
- **Gate strengthened, not relaxed.** A new test in each file (`sources_and_clear_are_one_assignment`, `irq_sources_and_clear_are_one_assignment`) refuses all four removed assignments by text and asserts that `irq_status <=` appears exactly twice — reset plus the merged update. Reintroducing the race now *fails* the suite instead of satisfying it. Assertions on this module go up, not down.
- Scope: this lands the RTL fix only. `formal/interrupt_controller_props.sv`, the regression witness the wave-547 campaign wrote for this defect, is not on `master` and is not part of this change.
- **Not verified by CI, and that is stated rather than assumed:** no workflow runs `cargo test -p t27c` (#2288, #2292), so these tests are checked by nobody today. The RTL claim above rests on the simulation above, not on a green check.

Closes #1967
