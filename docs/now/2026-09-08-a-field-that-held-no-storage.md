# NOW -- A field that held no storage (2026-09-08)

## A field that held no storage (Closes #3446, Refs #3445, #3443)

- The parity table covered PARAMETER position only. Extending it to return and field position found two more defects in one run, and both were invisible to the first table. `struct Holder { f : [4]u8, g : i32 }` reached C as `uint8_t* f;` -- the field held **no storage at all**, so `h.f[0] = 1` wrote through an uninitialised pointer, and the same struct measured **16 bytes in C against 8 in Rust and Zig**. Measured by compiling and printing `sizeof`, not inferred. Three backends agreed and C was alone. **65 fields across 31 specs.**
- Return position is the second, and it is worse in kind: `fn probe(v: i32) -> [4]u8` emits `uint8_t* probe(...)` returning a stack local -- `warning: address of stack memory associated with local variable 'a' returned`, **18 sites in 14 files**. Filed as #3445 rather than fixed, because the obvious repair was tried and MEASURED WORSE: normalising `[N]T` to the `[T; N]` machinery took errors 3849 → **3878** and compiling files 296 → **287**, since the type moves to a struct while the indexing and the call sites do not. Built, measured, reverted; the numbers are in the issue.
- The field repair is the narrow one and it holds: errors **3849 → 3825**, files that compile **296 → 301**. Per file: **six better, one worse**. The one regression is named rather than netted away -- `zamolodchikov_4d_conjecture` gains one error because a field that is now a real array is initialised from a function returning `double*`, which is #3445 becoming visible. Five files go from failing to clean.
- Three positions, three answers, and the narrowing is the design: a parameter wants `T x[static N]` (the spelling that checks the caller, #3435), a field wants `T f[N]`, and a return cannot be an array in C at all.
- **A mutant survived and is written down rather than papered over.** Deleting the `;` guard in `c_array_field` changes nothing any test catches: `[u8; 4]` reaches the emptiness check anyway. The guard is redundant TODAY, is kept as intent, and the position now has its own test. Four other mutants died.
- Two candidates were refuted before publication, one per pass now: enum width in Verilog is 32 in BOTH Verilog paths, so `HwType::Enum`'s 1-bit computation is not a disagreement between them and there is no finding. The other was `[]const u8` last pass.
