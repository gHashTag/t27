# NOW -- t27b: module-level var, the StmtAssign(undeclared) family (2026-10-05)

## module-level var in t27b (Closes #6294)

- A typed module `var` with a compile-time initializer (scalar, enum, struct, array) now becomes a writable global (`ExprKind::Global`, `Program::globals`). Before, t27b read it as a constant and refused every assignment to it as `StmtAssign(undeclared)`.
- `t27c test-report` runs each test in its own process. To match that, the JIT copies the initial bytes back into its heap region on every call, and the interpreter resets them on every host entry. An object file refuses the shape as `VarDecl(module, object file)`, because Mach-O output has no writable section yet.
- Shapes that the reference's Zig cannot compile are refused by name, never guessed:
  - `StmtAssign(module var in test)`
  - `StmtLocal(shadows module var)`
  - `ExprIdentifier(renamed module var)`
  - `ExprIdentifier(var at comptime)`, for a module var in an invariant
  - The reference bugs behind these are #6295.
- `t27b corpus specs`:
  - Pass goes 246 -> 258 and test fails 4 -> 6. The new fails are hir_tb and timing_tb, which fail the same tests as the reference.
  - Rejected goes 687 -> 670.
  - Mismatch stays 0.
  - Timeout goes 0 -> 3: axi4_tb, clock_domain_tb and gf16_accel_tb spin on a module flag nothing sets, and the reference times out on them too.
  - The 12 new passes agree test for test with `t27c test-report`.
- What is left of `StmtAssign(undeclared)` is a different shape: the discard `_ = x;` (31 files) and a loop `i` (3 files).
