# NOW -- turn_stop.t27: precise control over Queen actor turn stopping (2026-10-09)

## What

A new card `specs/queen/turn_stop.t27` adds precise control over what happens when a Queen actor turn is killed, addressing three critical problems:

1. **Spinning worker threads kept counting 200 ms after `terminate()`** - only a process kill stops work
2. **Killed reviews keep their row and z.ai key lane until timeout** - during stalls more than `REVIEWER_CONCURRENCY` reviews run at once  
3. **Process isolate killed with SIGKILL leaves child processes running** - `sh -c 'sleep 30 & wait'` killed that way leaves its `sleep` running

## How

The module reuses `actors.t27` where it already decides, and adds four new abstractions:

### TURN_STOP_GRACE_MS (3000ms)
- How long a turn has after its abort signal (`stop_signal` X_SHUTDOWN) before escalation to X_KILL
- FR-001: grace + kill landing fits inside `LANE_FREE_MS`, grace < `WORKER_SHUTDOWN_MS` (5000)

### step_on_abort(started, writes_shared, finalizer)
- FR-002: finalizer always runs; shared write already underway finishes; everything else cut
- Returns true if work should continue, false if work should be cut

### escalation(kill_stops, work_ended)  
- ESC_NOTHING, ESC_KILL_GROUP (whole process group, never one pid), or ESC_ABANDON
- FR-003: never kills one pid; unkillable turns are abandoned, not claimed stopped

### in_flight(running, held_after_kill)
- FR-004: what a concurrency bound counts - held turns count, saturates instead of wrapping

## Integration

The `turn_stop_orchestrate()` function coordinates all timing and decisions:
- During grace period: uses `step_on_abort()` to decide what continues
- After grace period: uses `escalation()` to determine kill strategy  
- Always: uses `in_flight()` to update concurrency counts
