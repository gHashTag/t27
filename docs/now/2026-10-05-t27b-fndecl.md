# NOW -- t27b: functions with more than 8 parameters (2026-10-05)

## t27b stack parameters (Closes #6312)

- `FnDecl` was the top of the `t27b corpus specs --blockers` greedy order at master 1318adf6d (+15 files), and all 15 were one shape: a fn with more than 8 parameters (tnf256/512/1024 `exp_offset`, `on_comb` with up to 24 parameters in `specs/ternary/gft_*.t27`, fpga `stdlib.t27`, `ternary_mac_group.t27`, `bitnet_*.t27`).
- Past the 8th parameter of a class (x0-x7, d0-d7) the rest go on the stack, one full word each in parameter order (`Program::stack_args`); the callee reads them at `[x29 + 16 + 8*s]` and re-normalises narrow values. That is t27b's own convention (Apple arm64 packs narrow stack arguments), so such a fn joins `internal_abi` and an object file does not export it.
- `t27b corpus specs`: pass 296 -> 311, rejected 633 -> 618, mismatch 0 -> 0; each of the 15 also passes `t27c test-report` with the same test count.
- The other `FnDecl` refusals now name their shape: `FnDecl(untyped param)` (7 files carry it: a `struct {}` parameter type, or a `comptime T: type` parameter that the front-end hands over without a type), `FnDecl(comptime param)`, `FnDecl(duplicate)`, `FnDecl(too many params)` (cap 64).
- Tests: `stack_parameters_reach_the_callee_in_order`, `f64_and_integer_stack_parameters_interleave`, `fn_declaration_rejections_are_precise` in `cli/t27b/tests/source.rs`; their programs match `t27c test-report` (5 of 6 with one deliberate fail, and 2 of 2). Mutation controls: a wrong stack slot and a missing sp bias on a spilled temp each fail them.
