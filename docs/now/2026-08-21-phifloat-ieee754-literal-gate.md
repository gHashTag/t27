# `PhiFloat.v` binary64 literals now checked against IEEE 754

- Confirmed the defect on freshly-fetched `master` (`dcff097d2`) before writing anything: `.github/workflows/coq-kernel.yml:93` runs `./target/release/t27c validate-phi-identity`, and the only `assert` in `scripts/validate_phi_f64.py` is line 23, `assert verify == x, f"decode mismatch: {verify!r} != {x!r}"` — an internal decode round-trip inside `f64_params`. That script never opens `coq/Kernel/PhiFloat.v`, so the file header's claim "Mantissas/exponents must match `scripts/validate_phi_f64.py`" named nothing enforceable.
- Recomputed the four literals independently: `phi_mantissa = 7286977268806824`, `phi_exponent = -52` (bits `0x3FF9E3779B97F4A8`, `0x1.9e3779b97f4a8p+0`); `one_mantissa = 4503599627370496`, `one_exponent = -52`. `fl(phi*phi)` and `fl(phi+1)` are the same double, `5895288448088660 * 2^-51 = 0x4004F1BBCDCBFA54`, residual exactly `0.0` — matching `phi_sq_f64_hex` in `conformance/FORMAT-SPEC-001.json`.
- Added `t27c validate-phi-f64-literals` (`bootstrap/src/phi_f64_literals.rs`): it reads the four literals out of `coq/Kernel/PhiFloat.v` with line-anchored patterns that include the Coq type, and compares each against parameters decoded from doubles computed in Rust from `(1 + sqrt 5) / 2` and `1.0`. No expected value is copied out of the Coq file — that would be a tautology; the only constants written down are the IEEE 754 field widths. Wired into step 8 of `.github/workflows/coq-kernel.yml` beside `validate-phi-identity`, under the existing `set -eux`, and `bootstrap/src/phi_f64_literals.rs` added to the workflow's `paths:` so the gate's own source cannot be edited into a no-op unobserved.
- Proved it bites: six mutants, one per guard, each planted alone in `coq/Kernel/PhiFloat.v` and reverted byte-for-byte (sha256 `b07c4c5864607e88903e64cd85c9caccfa3dc231c57a4007f0987db71f91d05d` restored, gate green again). Each exits 1 naming file, line, found value and required value — `phi_mantissa` 4→5, `phi_exponent` −52→−51, `one_mantissa` +1 ulp, `one_exponent` −52→−53, the `phi_mantissa` definition deleted (absence must not pass), and a shadowing duplicate. Mismatches are collected rather than aborted on the first, so one bad literal does not leave the other three guards unexercised.
- Measured which literals the *Coq* proof already pins, rather than assuming: `phi_sq_f64_ff_eq_phi_plus_one_f64_ff` is `vm_compute; reflexivity` on `fl(x*x) = fl(x+one)`, so it is value-sensitive. Over the ±5000 ulp window around φ, `7286977268806824` is the **only** mantissa satisfying it — so a small `phi_mantissa` typo would have broken the Coq build. But on the `one` side three mantissas satisfy it, and `4503599627370497` (= `1.0000000000000002`) is also canonical, so `one_f64_bounded`, `phi_sq_f64_ff_eq_phi_plus_one_f64_ff`, `phi_identity_contract`, `coqchk` and `validate-phi-identity` all stay green while `one_f64` is no longer `1.0`. That is the fail-open this gate closes, and it is the mutant pushed to CI as evidence.
- Nothing weakened: no `|| true`, no `continue-on-error`, no existing assertion relaxed, no case dropped. The stale "must match that script" line in the `PhiFloat.v` header was corrected to point at the gate that now enforces it.
- Noted, not changed, filed separately as #2356: the required context `check` is the job `check` in `.github/workflows/check-now-freshness.yml`, whose only step is `echo "Checking repository freshness..."` — a required check that cannot fail.
