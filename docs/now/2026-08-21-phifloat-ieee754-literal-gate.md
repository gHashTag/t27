# `PhiFloat.v` binary64 literals now checked against IEEE 754

- Confirmed the defect on `master` (`6b19d8be`) before building: `.github/workflows/coq-kernel.yml:93` runs `./target/release/t27c validate-phi-identity`, and the only `assert` in `scripts/validate_phi_f64.py` is line 23, `assert verify == x, f"decode mismatch: {verify!r} != {x!r}"` — an internal round-trip inside `f64_params`. That script never opens `coq/Kernel/PhiFloat.v`, so its header claim "Mantissas/exponents must match `scripts/validate_phi_f64.py`" named nothing enforceable.
- Established why the neighbouring checks cannot cover it: `validate-phi-identity` computes φ from `(1.0 + 5.0_f64.sqrt()) / 2.0` itself and checks `phi^2 + phi^-2 = 3`, which holds whatever the Coq file says; and `phi_f64_bounded` proves only `SpecFloat.bounded 53 1024 phi_mantissa phi_exponent = true`, i.e. that the pair is a *canonical* binary64 — true of a great many pairs that are not φ.
- Added `t27c validate-phi-f64-literals` (`bootstrap/src/phi_f64_literals.rs`): reads `phi_mantissa`, `phi_exponent`, `one_mantissa`, `one_exponent` out of `coq/Kernel/PhiFloat.v` with line-anchored patterns that include the Coq type, and compares each to parameters decoded from doubles computed in Rust from `(1 + sqrt 5) / 2` and `1.0`. No expected value is copied from the Coq file; the only constants written down are the IEEE 754 field widths.
- Wired into step 8 of `.github/workflows/coq-kernel.yml` next to `validate-phi-identity`, under the existing `set -eux`. Added `bootstrap/src/phi_f64_literals.rs` to the workflow's `paths:` so the gate's own source cannot be edited into a no-op without a run observing it.
- Proved it bites: six mutants, one per guard, each planted in `coq/Kernel/PhiFloat.v`, run, then reverted with the blob hash checked back to `fd857c2b2ba4e3ec8aee8e91b59903ca3a949485`. Each exits 1 and names the file, line, found value and required value — `phi_mantissa` last digit 4→5, `phi_exponent` −52→−51, `one_mantissa` +1, `one_exponent` −52→−53, the `phi_mantissa` definition deleted (absence must not pass), and a shadowing duplicate appended. Mismatches are collected rather than aborted on the first, so one bad literal does not leave the other three assertions unexercised.
- Nothing weakened: no `|| true`, no `continue-on-error`, no existing assertion relaxed. The stale "must match that script" line in the `PhiFloat.v` header was corrected to point at the gate that now enforces it.
- Noted, not changed: `.github/workflows/check-now-freshness.yml` (job `check`, a required context) is still `echo "Checking repository freshness..."` and cannot fail; and `scripts/validate_phi_f64.py` remains print-only. Both are out of scope here and filed separately.
