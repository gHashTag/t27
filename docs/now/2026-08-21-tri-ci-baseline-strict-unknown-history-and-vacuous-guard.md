# NOW -- tri ci baseline: an unreadable history is not a zero, and the guard now reaches the command (2026-08-21)

## Repairing #2360, not reverting it (Closes #2361)

#2360 merged at `cb446ea128c7b60cee6e100a49300d227455993d` while a review of it
was in flight. Its ranking idea is right and its other measurements reproduce
exactly (`check-now-freshness` 1446/2, `seal-staleness-warn` 169/0,
`loop-tools-gate` 12/0, `catalog-count-gate` 37/0). Three things rode along with
it. All three are fixed here; nothing is undone.

- **`--strict` failed open on unknown history.** `gh()` bails on any non-zero exit, so a rate limit or a 502 became `""`, `num("")` returned `-1`, and `-1` lost both `> 0` tests it met: the hole dropped out of the strict count *and* the verdict ladder printed `has never run anywhere at all` about a workflow whose history could not be read. Counts are now `Option<i64>`; `None` means "the API did not say" and propagates to the exit code. A gate that has **never run anywhere** (`0 runs, 0 failures`) is no longer exempt either — that is the strongest form of "no green state has ever been observed", not the weakest. The one exemption that was actually earned survives: a gate that HAS run, often, and has never once concluded `failure`.
- **The same swallow existed one level up and is closed too.** An unreadable default-branch run count used to mean "this workflow has a baseline", which deleted the finding outright. Unreadable workflows are now printed under `workflows the sweep could not measure` and counted toward `--strict`. Deliberate exception, measured: a **404** from the contents API *is* an answer — 12 of this repository's 54 registered active workflows have no file on `master` at all, and a workflow that is not on the default branch gates nothing there. `Fetch::Absent` keeps that apart from `Fetch::Failed`.
- **The guard tested `std::slice::sort_by`, not `tri ci baseline`.** `a_gate_that_has_never_failed_ranks_below_one_that_has` copied the production sort and the `loud` predicate into its own body and asserted against its own local vector. Two mutants planted in the shipped file survived: inverting the **production** sort (`3 passed; 0 failed`) and replacing `if strict && loud > 0` with `if false`, making `--strict` a permanent no-op (`3 passed; 0 failed`, only `warning: unused variable: strict`). Extracting the whole test into a file containing **no production code at all** still compiled and passed.
- **The ranking and the strict decision are now callable, and the tests call them.** `rank`, `severity`, `verdict`, `alarming`, `strict_verdict`, `count` and `is_not_found` are lifted out of the command body. Both previously-surviving mutants now die: the inverted production ranking fails two tests (`left: ["measured-zero.yml", "never-ran.yml", "unreadable.yml", "goes-red.yml"]`), and forcing `strict_verdict` to `None` fails `assertion failed: strict_verdict(true, &red, &[], "master").is_some()`. The same extraction into a production-free file now yields **38 compile errors** naming 10 distinct production items — the functions `rank`, `severity`, `verdict`, `alarming`, `strict_verdict`, `count`, `is_not_found`, `is_pr_gated`, `decode_b64` and the `Severity` type — and no binary.
- **Consumption proved separately, against the live API.** Repaired build: `tri ci baseline --repo gHashTag/t27 --strict` exits **1** with `1 PR gate(s) have no baseline on master and cannot be shown to be harmless`. Same build with production `rank` inverted and `strict_verdict` forced to `None`: exit **0**, and the printed order flips to `seal-staleness-warn.yml` first. `baseline()` really does call both.
- **The doc comment stated the old contract.** `/// Non-zero exit if any gate has no baseline. For use in CI.` was untouched by #2360 and had been false since it merged. Replaced with what `--strict` actually does.
- **`emit-bitexact` was never one of #2309's four**, and the false claim was in three places: the `cibase.rs` module doc, the #2360 NOW entry, and the test's doc-comment plus its `Hole { file: "emit-bitexact-gate.yml", … }` fixture asserted to rank first. All three corrected against live numbers. The NOW entry is a dated record, so the correction is **appended** to it and the original bullets are left standing.

**Severity: latent, not live.** `cibase.rs` is the only reference to `ci baseline`
anywhere in the tree, so no job changes colour today. But the flag says "For use
in CI", and it would have been wired up in the fail-open state.
