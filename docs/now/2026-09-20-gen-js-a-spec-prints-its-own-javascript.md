# NOW -- gen-js: a spec prints its own JavaScript (2026-09-20)

## The compiler gains a JavaScript backend, and a class of hand-written generator stops being necessary (Closes #4471)

- **Why it exists.** Our MCP servers run on JavaScript, and a `.t27` spec that describes one had no way to reach them. So every such spec grew a hand-written generator in a foreign language beside it -- and that generator, not the compiler, became the thing that decided what the artifact said. That is a hole in the compiler wearing the costume of a build script. `t27c gen-js` closes it: the artifact is printed by the compiler, and the bespoke generator does not exist.
- **Scope, stated in the file rather than discovered later.** `bootstrap/src/codegen_js.rs` lowers *declarations* -- consts, enums, structs -- into an ES module. It does not lower function bodies. A `fn`, `test`, `bench` or `invariant` in the input is **announced in a comment in the output**, never dropped in silence, because an artifact that is quietly missing something is worse than one that says what it left out.
- **The emitted module is data.** Nothing in it runs, so a spec cannot smuggle behaviour into a server through its own description.
- **A defect found by testing the thing rather than the tests.** `pub enum Sev { Info, Warn = 5, Error }` came out `Warn: 1`. The explicit discriminant lives on the variant NODE, in `value` -- not in a child, which is where the first draft looked -- so the backend silently substituted the position the variant happened to sit in. A wrong number that looks like a right one is the worst thing a code generator can emit. The node is now asked first, and the count resumes FROM the explicit value, so `Error` is 6 and not 2: the rule C, Rust and Zig already share.
- **Witnesses, not adjectives.** `habr-mcp`'s committed `habr_decls.mjs` regenerates **byte-identically** from its spec. Over 150 corpus specs: 116 generate, 34 are refused with a sentence naming the exact construct, **0 panics**. 11 unit tests in the backend cover the quoting rules, including a value whose own content is quotes and a U+2028 that would otherwise end a line inside the emitted string literal.
- **`bootstrap/src/compiler.rs` is not touched.** The backend reads `extra_kind == "string"` the same way the Zig backend does, and the frozen seal in `bootstrap/stage0/FROZEN_HASH` is unchanged -- no freeze ceremony was needed for this.
- **A census moved, and it is not this backend's.** `tools/census/quiet.txt` goes 141 → 142 in this commit. The new row is `queen-publish.yml:81` — `GH_TOKEN: ${{ secrets.GH_AGENT_TOKEN || github.token }}`, which arrived in `d7a1530ad` and was not re-blessed there. It is a YAML fallback expression, not a shell `||` swallowing an exit code, so the census **refuses** it correctly; the refusals are counted too, which is why the total moved. Re-blessed here because this is the commit the gate stopped, and a number that moves without a sentence is exactly what that ledger exists to prevent.
- **What this does NOT establish.** The escape table in `codegen_js.rs` is the compiler's third, beside `zig_escape` and `escape_for_fmt`. It is not a copy of either -- the U+2028/U+2029 arms exist for JavaScript alone -- but the overlap is real. Folding all three into one table with a target parameter is worth doing, and is deliberately not done here, where it would ride into a frozen file on the back of a new backend.
