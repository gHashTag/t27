# NOW -- The Trinity CLI and MCP commands from one verified registry (2026-09-12)

## S06 of gHashTag/trinity#988: one registry, repository-qualified IDs, and the server as it is (Closes #3568)

- Until today `specs/tools/README.md` and `docs/system/tooling.md` said gHashTag/trinity had no `tri` binary. It has one (`build.zig:2134`), with five dispatch layers, a 187-entry command table in `src/registry/command_table.zig`, an execute map with 180 live and 18 commented-out entries, a `parseCommand` of 322 string comparisons, an MCP server that advertises 210 tools from one literal, and documents that count 35, 47, 100 and 280. The one artifact that repository's own binary exports and its CI holds to the binary is `.trinity/registry.json` (`zig build export-registry`, the Registry schema check of `ci.yml`): 29 commands, the `mcp_enabled` subset of the table. S06 derives the Trinity cards from it and from nothing else.
- `specs/tools/catalog.t27` (module `ToolsCatalog`, `KIND = "tools-catalog"`) is the catalog contract at schema 2: every card carries `REPO`, `QUALIFIED_ID` (`<owner>/<repo>:<family>/<name>`) and `SCHEMA = 2`; the 62 cards written before keep their short `ID` (the site route and the agents' `TOOLS` use it) and gain `QUALIFIED_ID = REPO:ID`; a Trinity card's `ID` is its qualified ID and never a short form, so the two same-named commands at the pin (`fpga`, `test`) can never be selected by the wrong repository. A legacy ID resolves through `LEGACY_IDS -> LEGACY_TARGETS` (62 pairs) and nothing else; a short ID naming only a Trinity command is refused with `use gHashTag/trinity:tri/<name>`; `resolve_legacy` is that rule as a function. Witnesses are `source-parse`, `registry-export`, `help-output`, `runtime`, and source parsing never claims runtime. The vocabularies of side effects, capabilities, modes, stabilities and namespaces are `src/registry/command_def.zig`'s. The counts the consumer measures to are constants the check holds. Ten findings, the first: the withdrawn claim.
- `specs/tools/trinity/tri/<command>.t27` (29 cards, module `tool_trinity_tri_<command>`): every field from the registry (`ABOUT`, `ARGS` from `input_params`, `ALIASES`, `NAMESPACE`, `MODE`, `STABILITY`, `CATEGORY`, `JOB_TIMEOUT`, `SIDE_EFFECTS` and `CAPABILITIES` as the registry's `side_effects`, `MCP_*`, `EXAMPLES`) and from the dispatcher (`ROUTED`, `ROUTE_KIND`, `ROUTE_NOTE`: 17 by the execute map, 6 by `parseCommand` only, 6 by nothing -- `blindspots`, `wallet`, `mesh`, `reputation`, `hardware`, `conscious`, whose MCP tools have no CLI behind them), `EXIT_CODES` and `RESULT` as they are (UnifiedOutput status at exit 0; the sysexits mapping of `observability.zig` is reached from no caller), `COLLIDES_WITH`, `WITNESS = "registry-export"`. A card is data: the C backend does not lower zero- or one-element arrays, so cards carry no test block and the tool is the check. The 62 legacy cards gained the three schema 2 fields.
- `specs/tools/mcp_protocol.t27` (`McpProtocol`, `KIND = "mcp-protocol"`) states what `tools/mcp/trinity_mcp/server.zig` does with a JSON-RPC message: stdio only (the HTTP, SSE and WebSocket transports beside it are imported by nothing), Content-Length or bare-line framing in, Content-Length out, seven methods matched as substrings of the raw text, no negotiation (the literal initialize result names 2024-11-05), notifications and unknown methods answered with silence (`-32601` exists in `errors.zig`, which nothing imports), a `tools/list` literal of 210 objects of which 32 are malformed JSON and whose footer closes one brace too many, `tools/call` routed exact then prefix (25) then to a generic executor that strips `tri_` and runs the command bare (fifteen advertised tools land there; an unknown tool is never refused), failures as `isError` results, no cancellation (`cancellation.zig` not imported), no timeout, no permission gate at the server (`security.zig` not imported; the only gate in the tree is tri-api's `permissions.zig`: deny over allow over a default that allows `read_file` and `grep`), ten resources, five prompts, the needle server's differences and the client that never reads the initialize reply and so discovers zero tools. Every decision is a function; five tests.
