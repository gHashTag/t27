## Thirty-two was not a decision about GF16 (Closes #3442, Refs #3443)

- Five repairs in a row shared one shape -- a single t27 declaration lowering to different guarantees per backend -- and each was found by accident, one at a time. `tools/backend_parity_table.py` prints the four answers side by side instead. On its first run it produced three candidates and refuted a fourth.
- `GF16` reached Verilog as `[31:0]`. The finding is not the number, it is the neighbour: `NoSuchTypeXY` also gives `[31:0]`. **32 was the unknown-type default**, and this project's flagship type was indistinguishable from one the backend has never heard of. The same file already knows better -- `HwType::GF16.hw_width()` returns 16 and `HwType::GF16.verilog_range()` returns `[15:0]`, both with **passing tests**. Two readers of one type, one of them green, and 2598 tests passing while it was wrong.
- Three spellings, three sizes of one bug: bare `GF16` 32 instead of 16; qualified `gf16::GF16` also 32, so one type had two widths depending on how the spec wrote it; and `[4]GF16` **32 bits in total**, eight per element, a quarter of the data, because GF16 was not among the element types that get the product treatment. Measured over 583 generated files: **119 sites in 3 files** for the bare form, **278 in 8** for the qualified, and one struct that becomes lowerable at 48 bits. Every added line carries `[15:0]` and every removed one `[31:0]`, with a single matching exception -- a three-GF16 tuple return, `[95:0]` to `[47:0]`.
- **The load-bearing test is the negative one.** A fix that widened the default to 16 would pass every positive assertion in the file; the mutant doing exactly that is killed only by `an_unknown_type_still_takes_the_thirty_two_bit_default`. Four mutants, four dead.
- A fourth candidate was **refuted by reading the code rather than shipped**: `[]const u8` lowering to Rust's `&'static str` looks like a type change, and it is a deliberate, load-bearing choice -- the HashMap key lowering asks this very mapping for its key type. A table proposes; it does not conclude.
- Two more from the same table are filed as **latent with a population of zero** (#3443), stated as zero up front: a nested array parameter emits `[3]u8* x` into a C header (`error: expected ')'`), and `tri` has no C spelling at all (`unknown type name`, zero typedefs). No spec exercises either today.
