# NOW -- tri mutate spec: a hang and a mutant zig rejects are no longer kills (2026-10-06)

## cli/tri/src/mutate.rs, .github/workflows/cli-tri.yml (Closes #7148)

- The defect: `tri mutate spec` ran `t27c gen` + `zig test` under one clock and called every non-zero exit a kill. A hang (the clock ran out) and a compile error both raised "killed", and neither was listed by line. Measured on one probe spec (md5 a72670c1..., Railway lab, zig 0.16.0, the same t27c, the two runs back to back): master's tri printed "22 of 24 killed (20 by `zig test`, 0 by a gen failure, 2 by a hang)"; this branch prints "17 of 24 killed (10 by a failing test, 7 by an invariant at compile time); 2 survived, 3 hung, 2 unviable." Five of the 22 were not a check noticing the mutant.
- Each mutant now runs in three steps, each on its own `--timeout` clock: `t27c gen`, `zig test --test-no-exec` (compile only), then the test binary. Only the test run outliving its clock is a HANG. gen or the compile outliving it is the machine's load, and the mutant is listed NOT RUN, not hung: a clock that includes the cold compile is the defect unclebob/mutator issue 1 reports.
- A compile error is not always unviable, and reading it so would undercount real kills: t27c lowers an `invariant` to a comptime block, so an invariant the mutant breaks fails the COMPILE, with zig's "note: called at comptime here". That is a kill (7 of the 17 above). zig's own comptime timeout, "evaluation exceeded 1000 backwards branches", is a HANG (probe line 63, `s = s + 1` -> `s = s` in a loop only an invariant runs). Any other compile error is UNVIABLE: zig rejected the mutant before a check ran (probe line 79, `buf[4 - 1]` -> `buf[4 + 1]`, "index 5 outside array of length 4"). Stryker and cargo-mutants keep compile errors out of the score the same way; PIT and Stryker count a timeout as detected, this tool lists it apart.
- The issue's second criterion assumed a mutant that leaves a parameter unused fails to compile. It does not: t27c emits `_ = a;` for every parameter and `_ = &i;` for every `var`, so such a mutant compiles and the tests judge it. The UNVIABLE test uses a type error instead (said on #7148).
- HUNG and UNVIABLE are listed by line, kind and reason, like the survivors; the summary keeps four counts that sum to the mutants run.
- Tests: 10 new in `mutate::tests`, 35 in all (was 25, `grep -c '^    #\[test\]$'`). Six run zig 0.16.0 on fixtures in t27c's lowered shape (a passing test, a failing one, an endless loop at run time, the comptime quota, a broken invariant, a type error); one runs `t27c gen` as `false`. `cargo test -p tri mutate` on the lab: 34 passed. Five hand-made regressions each turn a named test red: every compile error a kill (2 tests), the comptime note read before the quota (2), a compile past its clock a hang (1), a hang counted as killed (1), a failing run read as a survivor (1).
- cli-tri installs zig 0.16.0 before `cargo test -p tri` (the recipe bootstrap-tests.yml uses). That moves the pinned `shell` census from 300 to 301 `run:` steps (279 -> 280 whose shell the runner names), re-blessed in this commit; master's own pins pass at the base. The workflow edit is listed in `tools/policy/foreign-exceptions.txt` (standing owner rule, label owner-approved-foreign).
- Found on the way: master's tri reported a spec whose unmutated copy fails as "does not pass (Killed via ...)", and the copy failed for a reason outside the spec. t27c resolves `use a::b;` by walking up from the spec file for a `specs/` directory; the system temp dir has none, so t27c dropped the import, `gen` still exited 0 (#7176), and zig failed on `specs/policy/l2_generation.t27` with "use of undeclared identifier 'LIST_END'".
