## cli/tri/src/main.rs, specs/tri/lanes/lanes.t27, tools/duplicate_bodies_baseline.txt (Closes #8628)

- PRs #8601, #8614 and #8623 each mounted their gen-rust module on one line: `#[path = ...] #[allow(...)] mod x;`. `tri mods orphan` reads a line that starts with `#[path` as an attribute alone. So it gave the path to the next `mod` line, `mod renum;`, and `cli/tri/src/renum.rs` read as orphaned. The result: "Orphaned modules" was red on master with `cli/tri: orphaned rose 0 -> 1`. The three mounts are now two lines each, as the rest of main.rs writes them, and `tri mods orphan --gate` prints `ORPHAN CEILING: CLEAN`. Joining the last three lines of `cmd_lab` and of `cmd_actors` pays for the three new lines: main.rs is +8 -9.
- Duplicate bodies: lanes.t27 `pr_end` was receipt.t27's `object_end` written again, and now calls it. receipt.t27 `line_end` is report.t27's body, and it stays a copy, ledgered as `line_end 2`. If receipt.t27 imports it from report.t27, every importer of receipt.t27 inlines report.t27 too. receipt's `V_BLOCKED` (3) and report's (2) then collide and drop out, so metrics.t27 stops compiling. The gen closure also pulls items named only inside string literals ("read" pulls report's `read`). That defect is #8630. `bits` and `clear` were red in the scan before these PRs and are not theirs.
