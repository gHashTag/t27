# NOW -- An instrument that cannot see must not report health (2026-09-20)

## Three green runs that meant the opposite of what they said (Closes #4314)

- **The feeder.** `queue_idle()` returned `False` when the Queen's status endpoint did not answer, and `False <= 0` is `True` in Python, so the caller printed `swarm busy - nothing added` and exited **0**. A scheduled run that fed nothing, said the opposite of what happened, and went green. It now returns `None` and the run exits 2: a feeder that cannot see the swarm has not measured it busy, it has not measured it at all.
- **The pusher.** Every `gh` helper returns its default on failure and every default is a number, so a rate-limited token collapses the board to zeros -- and an all-zero board is exactly the shape of `out-of-fuel`. The watchman would have filed "nothing is dispatchable" about a repository with a full backlog. The reading now carries `github_readable`, and a reading with zero open issues (which this repository has never had) is refused the same way a silent status endpoint already was.
- **A stale comparison.** `STALE_READING_HOURS = 6` was declared with the comment "A reading older than this is not evidence about now" and read by nothing. `not-evolving` now skips when the previous reading is older than that.
- **And the noise.** While any rule held, the pusher commented on the pulse issue every reading -- 96 a day at the new fifteen-minute cadence. It now comments only when the SET OF FIRED RULES CHANGES; the body is rewritten every time and is always current. A log nobody can scroll is a log nobody reads, which is how the next real stall gets missed.
- All four were found by an adversarial reading of the swarm's own instruments, not by a failure: each one was waiting for the day the token expired.
- What this does NOT fix: `dispatches.unreviewed` counts every finished row with no verdict, including rows that were reaped and will never be reviewed. Observed falling (24 -> 18) on 2026-09-20, so it is not the monotonic counter it was reported to be, and the `review-backlog` rule requires a RISE. Left alone until it is measured against the database rather than argued about.
