# NOW -- the L2 GENERATION rule lives in a spec; the Python only feeds it (2026-10-06)

## specs/policy/l2_generation.t27, gen/c/policy/l2_generation.c, tools/l2_regen_check.py (Closes #7113)

- The rule moved. Which gen/ files a change must show are t27c output, how a gen/ path names its spec, which t27c subcommand writes which backend directory and how a `use` line names a spec were decided in Python. They are now `plan_all()` in module PolicyL2Generation, and its gen-c copy is what CI runs. The Python gathers the facts (diff, tracked copies, specs, `use` lines), builds the copy with a one-line C main and compares t27c's bytes; it decides nothing. Same shape as the Only-t27 gate in `specs/policy/own_language.t27`, whose helpers it imports instead of copying.
- A defect the move found: the Python mapped gen/zig to `t27c gen-zig`, which does not exist, so a correct zig copy would have read as a hand edit. zig is `t27c gen`; an invariant pins the backend table, `gen-zig` included as absent.
- A PR is judged by the BASE's copy of the rule, so a PR cannot loosen the rule that judges it. A base without the copy (the PR that adds it) and `--all` read the tree's copy, and then that copy is checked first against its own spec. Without that row, a tree copy rewritten to print only `--end` planned nothing and passed (control 5, exit 0); with it the same head prints "RULE NOT OUTPUT", exit 1.
- Fail closed: missing section markers, a diff line without a tab, a quoted path, a copy with no backend, extension or spec, more `use` lines than the mark buffer, and a plan that did not fit (no `--end` line) each fail; none reads as "not checked, fine".
