# NOW -- t27b lowers f32 in s registers (2026-10-05)

## t27b type f32 (Closes #6448)

- `Ty::F32` joins the t27b IR, interpreter and AArch64 backend: single precision lives in s registers (the double FP encodings with bit 22 clear, `fmov s/w`, `fcvt` between precisions), canonical in a register like a u32. The f64 path from #6286 is shared, not copied: `fp_in` / `fp_out` / `fp_op` in `codegen.rs`.
- Literals round like Zig's comptime_float -> f32. An inexact literal whose f64 is exactly an f32 rounding boundary is refused, because Zig rounds the f128 and the f64 cannot tell: `1.0000000596046447753906250001` is 0x3f800001 in Zig and `1.00000005960464477539062499` is 0x3f800000, one f64. An integer literal must be an f32 exactly (`16777217` is a Zig compile error).
- f32 with f64 peers to f64 (`fcvt d, s`, exact); `@floatCast` with a result type rounds f64 to f32 (inf on overflow, as Zig's runtime cast); `@floatFromInt` / int `as f32` convert in one rounding; `@intFromFloat` from f32 shares the f64 bounds check. The lowering helpers live in the new child module `cli/t27b/src/lower_float.rs`.
- New tests: 14 encoder words from clang + objdump, f32 interpreter-vs-JIT differentials over the f32 edge values (arith, compares, conversions, both `@floatCast` directions incl. midpoints, AAPCS64 with s/d/x interleaved), a source program whose verdicts equal `t27c test-report`, and the refusals.
