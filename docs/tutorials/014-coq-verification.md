## Introduction

t27 integrates with Coq, a proof assistant based on the Calculus of Inductive Constructions. This tutorial covers formal verification: writing specifications, proving theorems, and generating verified code.

## Part 1: Why Formal Verification?

### Testing vs. Proving

| Aspect | Testing | Formal Verification |
|--------|---------|---------------------|
| Coverage | Finite cases | All cases |
| Guarantee | Probabilistic | Mathematical |
| Effort | Low | High |
| Confidence | Good | Absolute |
| Failure modes | Runtime bugs | Specification errors |

### The t27 Verification Stack

```
.t27 Spec → Coq Theorems → Proofs → Verified Code
    ↓            ↓            ↓          ↓
  Semantics    Properties   Certainty   Correctness
```

### When to Use Formal Verification

Use Coq verification for:
1. **Critical correctness** — Cryptography, safety systems
2. **Mathematical properties** — The Trinity Identity
3. **Compiler correctness** — Code generation verification
4. **Protocol correctness** — Network protocols, consensus

## Part 2: The Verification Workflow

### Step-by-Step Overview

1. **Write spec** — Define module in `.t27`
2. **Generate Coq** — `tri gen-coq module.t27`
3. **Define theorems** — Specify properties to prove
4. **Write proofs** — Use Coq tactics
5. **Verify** — `tri verify-coq module.v`
6. **Extract** — Generate verified code

### Quick Example

```t27
module VerifiedAdd {
    // The specification
    fn verified_add(a: nat, b: nat) -> nat {
        return a + b;
    }

    // The property to prove
    theorem "add_commutative" {
        forall a: nat, b: nat {
            verified_add(a, b) == verified_add(b, a)
        }
    }
}
```

## Part 5: Writing Theorems in t27

### Theorem Syntax

```t27
module Proofs {
    // Property with forall quantifier
    theorem "property_name" {
        forall var1: type1, var2: type2 {
            expression == expected
        }
    }

    // Property with exists quantifier
    theorem "existence" {
        exists x: type {
            condition(x)
        }
    }

    // Property with implication
    theorem "implication" {
        forall x: type {
            premise(x) => conclusion(x)
        }
    }
}
```

## Part 6: Writing Coq Proofs

### Proof Structure

```coq
Theorem phi_squared_is_phi_plus_one : PHI * PHI = PHI + 1.
Proof.
  (* Your proof goes here *)
Qed.
```

### Proving phi_squared = phi + 1

```coq
Require Import Reals.
Open Scope R_scope.

Definition PHI : R := (1 + sqrt 5) / 2.

Theorem phi_squared_is_phi_plus_one : PHI * PHI = PHI + 1.
Proof.
  unfold PHI.
  field.
  (* Now we need to prove (sqrt 5)² = 5 *)
  rewrite sqrt_square.
  auto with real.
Qed.

Theorem trinity_identity : PHI * PHI + 1 / (PHI * PHI) = 3.
Proof.
  rewrite phi_squared_is_phi_plus_one.
  (* PHI * PHI = PHI + 1 *)
  replace (1 / (PHI * PHI)) with (1 / (PHI + 1)).
  {
    rewrite <- (phi_squared_is_phi_plus_one) at 2.
    field.
    (* Simplify: (PHI + 1) + 1/(PHI+1) = 3 *)
    (* Use golden ratio property: PHI = 1 + 1/PHI *)
    (* This requires knowing PHI - 1 = 1/PHI *)
    apply golden_ratio_reciprocal.
  }
  (* Prove 1 / (PHI * PHI) = 1 / (PHI + 1) *)
  rewrite phi_squared_is_phi_plus_one.
  reflexivity.
Qed.

Theorem golden_ratio_reciprocal : 1 / PHI = PHI - 1.
Proof.
  unfold PHI.
  field.
  (* Prove (1 + sqrt 5) * (sqrt 5 - 1) = 4 *)
  ring.
Qed.
```

### Automated Tactics

```coq
(* Theorem with automation *)
Theorem add_comm : forall n m : nat, n + m = m + n.
Proof.
  induction n.
  - auto.                   (* Base case: 0 + m = m + 0 *)
  - intros m.               (* Inductive case *)
    rewrite IHn.            (* Apply induction hypothesis *)
    auto.                   (* Simplify *)
Qed.

(* Using ring for arithmetic *)
Theorem mul_add_distr :
  forall n m p : nat, n * (m + p) = n * m + n * p.
Proof.
  intros.
  ring.
Qed.
```

## Part 7: Proving Program Correctness

### Specifying a Function

```t27
module SortedList {
    // Insert into sorted list (maintains sorted property)
    fn insert_sorted(list: list<int>, value: int) -> list<int> {
        if len(list) == 0 {
            return [value];
        }

        if value <= list[0] {
            return [value, ...list];
        }

        return [list[0], ...insert_sorted(list[1:], value)];
    }

    // Sorted predicate: list is non-decreasing
    predicate "is_sorted" {
        forall list: list<int> {
            len(list) <= 1 ||
            forall i: nat {
                0 <= i && i < len(list) - 1 =>
                list[i] <= list[i + 1]
            }
        }
    }

    // Theorem: insert_sorted maintains sorted property
    theorem "insert_preserves_sorted" {
        forall list: list<int>, value: int {
            is_sorted(list) =>
            is_sorted(insert_sorted(list, value))
        }
    }

    // Theorem: element is in result if it was input or in list
    theorem "insert_contains_input" {
        forall list: list<int>, value: int {
            contains(insert_sorted(list, value), value)
        }
    }

    // Theorem: no elements lost
    theorem "insert_preserves_elements" {
        forall list: list<int>, value: int, x: int {
            contains(list, x) =>
            contains(insert_sorted(list, value), x)
        }
    }
}
```

### Proving insert_preserves_sorted

```coq
Require Import List.
Require Import Arith.
Import ListNotations.

Fixpoint insert_sorted (l : list nat) (v : nat) : list nat :=
  match l with
  | [] => [v]
  | h :: t =>
      if Nat.le_dec v h then v :: l else h :: insert_sorted t v
  end.

Fixpoint is_sorted (l : list nat) : Prop :=
  match l with
  | [] => True
  | [x] => True
  | h :: (m :: t) => h <= m /\ is_sorted (m :: t)
  end.

Theorem insert_preserves_sorted :
  forall (l : list nat) (v : nat),
  is_sorted l -> is_sorted (insert_sorted l v).
Proof.
  intros l v H.
  induction l as [| h t IH]; simpl.
  - constructor.  (* empty list is sorted *)
  - destruct (Nat.le_dec v h).
    + (* v <= h, prepend *)
      apply and_split.
      * assumption.
      * assumption.
    + (* v > h, insert in tail *)
      destruct t.
      * (* single element list *)
        constructor; auto with arith.
      * (* longer list *)
        apply and_split.
        -- (* h <= insert_sorted t v *)
          destruct (Nat.le_dec v a).
          ++ (* v <= a, v inserted first *)
            apply Nat.le_trans with v; auto with arith.
          ++ (* v > a, a first *)
            assumption.
        -- (* tail is sorted *)
          apply IH.
          apply and_project_2 in H.
          assumption.
Qed.
```

## Part 9: Coq Tactics Reference

### Basic Tactics

| Tactic | Description | Example |
|--------|-------------|---------|
| `intros` | Introduce variables | `intros x y H.` |
| `apply` | Use a theorem | `apply Nat.add_comm.` |
| `rewrite` | Replace using equality | `rewrite H.` |
| `reflexivity` | Prove x = x | `reflexivity.` |
| `auto` | Automatic solving | `auto with arith.` |
| `ring` | Prove ring equalities | `ring.` |

### Induction Tactics

| Tactic | Description | Example |
|--------|-------------|---------|
| `induction` | Induct on variable | `induction n.` |
| `destruct` | Case analysis | `destruct (Nat.le_dec n m).` |
| `case` | Case on constructor | `case l.` |

### Logic Tactics

| Tactic | Description | Example |
|--------|-------------|---------|
| `split` | Split conjunction | `split.` |
| `left` / `right` | Choose disjunction | `left.` |
| `exists` | Introduce existential | `exists x.` |
| `contradiction` | Derive False | `contradiction.` |

### Advanced Tactics

```coq
(* solve by searching for applicable theorems *)
eauto.

(* generalize hypothesis *)
generalize dependent x.

(* revert variable for induction *)
revert n.

(* apply theorem with specific parameters *)
apply (theorem_name arg1 arg2).

(* use classical reasoning *)
admit.

(* incomplete proof, to be finished later *)
Admitted.
```

## Part 10: Common Proof Patterns

### Arithmetic Proofs

```coq
Theorem add_assoc : forall n m p : nat,
  n + (m + p) = (n + m) + p.
Proof.
  intros.
  ring.
Qed.

Theorem add_0_r : forall n : nat, n + 0 = n.
Proof.
  induction n.
  - reflexivity.
  - simpl. rewrite IHn. reflexivity.
Qed.
```

### Induction Proofs

```coq
Theorem length_app :
  forall (A : Type) (l1 l2 : list A),
  length (l1 ++ l2) = length l1 + length l2.
Proof.
  intros A l1 l2.
  induction l1 as [| h t IH].
  - simpl. auto with arith.
  - simpl. rewrite IH. auto with arith.
Qed.
```

### Functional Correctness

```coq
Fixpoint factorial (n : nat) : nat :=
  match n with
  | 0 => 1
  | S p => (S p) * factorial p
  end.

Theorem factorial_gt_0 :
  forall n : nat, 1 <= factorial n.
Proof.
  induction n.
  - auto with arith.
  - simpl.
    rewrite mult_le_compat_l.
    auto with arith.
Qed.
```

## Part 11: CI/CD Integration

### GitHub Actions for Coq Verification

```yaml
name: Coq Verification

on:
  push:
    paths:
      - 'specs/**/*.t27'
      - 'verification/**/*.v'
  pull_request:
    paths:
      - 'specs/**/*.t27'
      - 'verification/**/*.v'

jobs:
  coq-verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Coq
        run: |
          sudo apt-get update
          sudo apt-get install -y coq coqide

      - name: Install t27
        run: |
          cargo install --path bootstrap

      - name: Generate Coq from specs
        run: |
          for spec in specs/**/*.t27; do
            tri gen-coq "$spec" > "verification/$(basename $spec .t27).v"
          done

      - name: Verify Coq proofs
        run: |
          for file in verification/**/*.v; do
            coqc "$file" || exit 1
          done

      - name: Extract verified code
        run: |
          coqc -R verification Verification verification/Main.v
```

### Makefile Integration

```makefile
.PHONY: coq-verify coq-extract clean

COQ_SOURCES := $(shell find verification -name "*.v")
COQ_OBJECTS := $(COQ_SOURCES:.v=.vo)

coq-verify: $(COQ_OBJECTS)

verification/%.vo: verification/%.v
	@echo "Verifying $<..."
	@coqc -R verification Verification $<

coq-extract: verification/Main.vo
	@echo "Extracting verified code..."
	@coqc -R verification Verification -Q verification Extraction verification/Main.v

clean:
	rm -f verification/*.vo verification/*.glob verification/.coq-native

generate-coq:
	@echo "Generating Coq from specs..."
	@for spec in specs/**/*.t27; do \
		base=$$(basename $$spec .t27); \
		tri gen-coq "$$spec" > "verification/$$base.v"; \
	done
```

## Part 12: Debugging Coq Proofs

### Common Issues

| Issue | Cause | Solution |
|-------|-------|----------|
| `Cannot unify` | Types don't match | Check type annotations |
| `No such variable` | Variable not in scope | Use `intros` properly |
| `Proof incomplete` | Missing steps | Continue with tactics |
| `Stack overflow` | Too deep recursion | Use `Functional Scheme` |

### Debugging Tactics

```coq
(* Show current goal *)
Show Proof.

(* Show all hypotheses *)
Print Assumptions.

(* Check if goal is provable *)
auto with arith.

(* Use tactical for step-by-step *)
Proof with (try auto with arith; fail).
```

## Part 13: Advanced Verification

### Hoare Logic (Imperative Programs)

```t27
module HoareLogic {
    // Precondition: { n >= 0 }
    fn factorial(n: nat) -> nat {
        let mut result: nat = 1;
        let mut i: nat = 1;

        // Invariant: result = (i-1)!
        invariant: result == factorial(i - 1);

        while i <= n {
            result = result * i;
            i = i + 1;
        }

        // Postcondition: { result = n! }
        return result;
    }

    theorem "factorial_correct" {
        forall n: nat {
            { n >= 0 } factorial(n) { result == factorial_impl(n) }
        }
    }
}
```

## Part 14: FAQ

### Q: How long does Coq verification take?

A: Simple proofs take minutes. Complex systems can take months. Start small.

### Q: Can I use Coq without proving everything?

A: Yes! Use `Admitted.` for incomplete proofs and return later.

### Q: What if my proof is too complex?

A: Break it into lemmas, use automation, or simplify the specification.

### Q: Does Coq work with all t27 features?

A: Most features are supported. Some advanced constructs may need workarounds.

### Q: Is verified code slower?

A: No! Extraction produces efficient code. The verification cost is development time only.
