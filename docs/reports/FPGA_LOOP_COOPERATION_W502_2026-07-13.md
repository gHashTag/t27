# Wave Loop 502 — Cooperation Variants

**Date:** 2026-07-13  
**From:** Wave Loop 501 close-out (#1470, branch `wave-loop-501`)  
**Next ring:** 12 (gen-verilog / Icarus semantics)  
**Anchor:** φ² + φ⁻² = 3 | TRINITY

This document proposes three concrete ways to continue from W501.  Wave Loop 501
removed the last `main`-specific hypothesis from the generic equivalence theorem,
so the next wave can widen the modeled language subset, harden the lowerability
gate, or start exporting the theorem to generated host code.

Each variant is independently valuable, scoped to one wave, and lists the exact
files/tests that would move.

---

## Variant A — Extend the equivalence proof to sequential constructs

**Goal:** add `ifThenElse` and `forLoop` to the Icarus-lowerable operational
semantics and the generic forward-simulation proof.

**Why now:**
- The theorem now covers any emitted function, but only for purely
  combinational statements.  Many practical t27 specs use simple `if` guards
  and bounded `for` loops.
- With reachability clutter gone (W499) and the entry-point assumption gone
  (W501), the induction shape is clean enough to add guarded big-step rules.

**Work:**
1. In `proofs/lean4/Trinity/IcarusLowerable/SemanticsTotal.lean`, add total
   evaluation rules for `Stmt.ifThenElse` and `Stmt.forLoop` on both the t27
   and shallow-Verilog sides.
2. In `proofs/lean4/Trinity/IcarusLowerable/Predicate.lean`, add structural
   combinationality/lowerability rules for the two constructs.
3. Extend `all_equiv` in
   `proofs/lean4/Trinity/IcarusLowerable/Equivalence.lean` with the
   corresponding induction cases.
4. Add scratch witnesses for conditional return and a bounded for-loop
   accumulator.
5. Re-run the full `./scripts/tri test` suite.

**Acceptance:**
- `lake build Trinity.IcarusLowerable.Soundness` green with zero `sorry`.
- At least two new scratch witnesses (conditional, for-loop) pass both t27 and
  emitted-Verilog evaluation.
- `./scripts/tri test` reports no new smoke failures.

## Variant B — Harden the Icarus lowerability gate with adversarial witnesses

**Goal:** grow and stress the Icarus-lowerable witness corpus so that the
classifier and the smoke gate stay aligned, and so that future emitter changes do
not silently reintroduce unsupported patterns.

**Why now:**
- W500 brought the Icarus smoke gate to 179 / 179 PASS with zero baselines.
- The classifier currently skips 294 specs with unmodeled placeholders.  The
  boundary between "intentionally skipped" and "should be lowerable" is only as
  strong as the witness set.
- W501 showed that the generic theorem now covers any emitted function; the next
  stress test is to add witnesses that exercise non-`main` entry points,
  nested calls, and mixed direct/indirect call shapes.

**Work:**
1. Add scratch witnesses for:
   - a non-`main` function called from another emitted function,
   - a chain of three emitted functions ending in a non-`main` leaf,
   - a helper that takes scalar struct parameters and returns a scalar,
   - a module with multiple non-`main` entry points.
2. Run `./scripts/tri verify --lean-lowerable` and compare classifier verdicts
   with Icarus smoke results for every new witness.
3. If a witness passes smoke but the classifier says `not_lowerable`, extend
   the predicate in
   `proofs/lean4/Trinity/IcarusLowerable/Predicate.lean`; if the classifier
   says `lowerable` but smoke fails, fix the emitter.
4. Add corresponding Lean witness modules and `native_decide` equivalence
   theorems.
5. Reseal all new `.t27` witnesses.

**Acceptance:**
- At least four new adversarial scratch witnesses pass both the classifier and
  Icarus smoke.
- `./scripts/tri verify --lean-lowerable` reports zero disagreements.
- `./scripts/tri test` reports 179 / 179 Icarus smoke PASS and no new baseline
  failures.

## Variant C — Export the generalized theorem to generated host harnesses

**Goal:** make the C/Zig test harness generated by `t27c` aware of the
`module_value_equiv_statement` contract, so that unit tests targeting non-`main`
functions are also covered by the Icarus equivalence theorem.

**Why now:**
- W501 proved that any emitted function preserves its value.  The generated
  host code currently runs `main` or ad-hoc helper calls against the emitted
  Verilog without linking those calls back to the formal contract.
- Closing this gap would make the formal model useful to the actual test
  harness, not only to hand-written Lean witnesses.

**Work:**
1. In `bootstrap/src/compiler.rs`, record the list of emitted (non-host-only)
   functions in the generated conformance / test metadata.
2. In `bootstrap/src/host/` or the generated Zig harness, emit a comment /
   manifest entry that maps each public non-host-only function to the
   `module_value_equiv_statement` instance that applies to it.
3. Add a conformance test or snapshot that checks the emitted manifest lists
   at least one non-`main` emitted function.
4. Add a scratch `.t27` module where the test block calls a helper directly, and
   verify the manifest captures it.

**Acceptance:**
- Generated host test metadata contains a `icarus_equiv_functions` list with
  every emitted function name.
- A non-`main` function appears in the list and passes Icarus smoke.
- `./scripts/tri test` reports no regressions.

## Suggested priority

1. **Variant A** — widens the modeled subset and is the next logical step for
   the generic proof.
2. **Variant B** — defensive hardening that can run in parallel with A or as a
   standalone wave if A uncovers new model-alignment issues.
3. **Variant C** — connects the formal theorem to the generated host harness;
   most valuable once A and B have stabilized the subset.
