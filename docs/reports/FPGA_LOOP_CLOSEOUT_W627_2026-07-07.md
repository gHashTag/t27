# FPGA Loop Closeout — Wave 627

**Issue:** #1598  
**Branch:** `wave-loop-627`  
**Date:** 2026-07-07  
**Variant:** A — `[73][2]^6 Pt` module-scope non-power-of-two outer-dimension array-of-struct, initialized from a function call, with indexed signed field writes and read-back.

---

## 1. Goal

Prove the t27 → Icarus lowering path can handle a module-scope mutable packed vector of outer dimension **73** (the next odd number after 71), where the variable is initialized by a function call and exercised with indexed signed writes to struct fields, then read back against a compile-time `expected` array.

---

## 2. Spec

- Witness: `specs/scratch/w627_bench_module_73x2p6_aos_var_call_write.t27`
- Type: `[73][2]^6 Pt` where `Pt { x: i16, y: i16 }`
- Total elements: 73 × 64 = **4,672**
- Packed vector width: 4,672 × 32 = **149,504 bits** (≈ **0.143 MiBit**)
- Spec size: ~16,300 lines (multi-line brace style required)

The module contains:

```t27
pub var dst: [73][2]^6 Pt = make_grid(32768);
pub const expected: [73][2]^6 Pt = make_grid(32768);
```

Both arrays are produced by a function `make_grid(offset: i16) -> [73][2]^6 Pt` that returns a fully expanded literal:

- Element value schedule: `(2*e + offset) % 32768` for `x`, `2*e + 1 + offset` for `y`.
- Signed writes flip `x` and `y` to `-value` at selected indices.
- Read-back tests compare `dst` against `expected`.

### Chosen indices for corner coverage

Because offset 0 never wraps for 4,672 elements, an explicit `make_grid(32768)` assertion is kept in the spec to preserve the modulo-wrap regression signal.

| Index | Test | Raw values after write |
|---|---|---|
| `[0][0][0][0][0][0]` | first element | `0/1` (no write) |
| `[72][1][1][1][1][1]` | last element | `-9342/-9343` |
| `[36][1][1][1][1][1]` | middle element | `-4736/-4737` |

## 3. Implementation

### 3.1 Spec generation

The W627 witness was generated by extending the W626 (71-row) module-scope lowerable spec with two additional outer rows, advancing the sequential element values by 128/256 respectively for the `2*e`/`2*e+1` schedule.

### 3.2 Multi-line literal style

Following the W584/W605/W626 style, every `[2]^k Pt` level is written with line breaks to avoid parser truncation on extremely long single-line literals.

```t27
Pt{
    .x = 9342,
    .y = 9343
}
```

### 3.3 Integration test

Added to `bootstrap/tests/icarus_lowerable.rs`:

## 5. Weak points and literature

### Weak points

1. **Non-power-of-two outer dimension 73** — must be strided correctly by compiler and reference model.
2. **Modulo-wrap signal preservation** — 4,672 elements never wrap with offset 0; explicit `make_grid(32768)` assertions keep the path covered.
3. **Mega-literal parsing** — ~16,300-line spec needs multi-line brace style to avoid truncation.
4. **Simulator resource headroom** — 0.143 MiBit is far below the 4-MiBit freeze threshold but should still be monitored.
5. **Index/value correctness** — moving from 71 to 73 rows changes last-row index to 72 and mid-row index to 36.

### Technical literature

- IEEE Std 1800-2017 packed-array semantics.
- Sutherland, *Synthesizable SystemVerilog* — packed struct/array support.
- Icarus Verilog issue #1171 — very-large packed-vector freeze threshold.
- Yosys issues #2677, #4653, PR #4100 — multidimensional packed arrays vs arrays of packed structs.
- cocotb `LogicArray` — reference-model mapping for packed arrays.
- Lutsig (CPP 2021) — verified array-read lowering.
- CIRCT `HWLegalizeModules.cpp` / SV dialect — scalarization of packed arrays.

## 6. Cooperation variants for Wave 628

### Variant A — `[75][2]^6 Pt` odd-outer ladder continuation (recommended)

- Outer dimension: 75.
- Total elements: 75 × 64 = 4,800.
- Packed width: 153,600 bits (≈0.146 MiBit).
- Risk: same module-scope lowerable style; direct extension of W627.
- Why recommended: maintains the established non-power-of-two pattern and is trivial to generate from W627.

### Variant B — `[2]^18 Pt` power-of-two deep dimension stress

- Outer dimension: 1; inner dimension: 2¹⁸.
- Total elements: 262,144.
- Packed width: 8,388,608 bits (8 MiBit).
- Risk: crosses the 4-MiBit Icarus freeze threshold; may require Yosys/Cocotb-only gate.
- Why considered: tests a very different shape and confirms the flattening path at a width that likely needs non-Icarus tooling.

### Variant C — conditional `if` reassignment in bench

- Keep `[73][2]^6 Pt` size but introduce an `if` statement inside the bench block that conditionally flips a subset of elements before comparison.
- Risk: exercises control-flow lowering in the bench harness, but may stray from the current wave’s pure packed-vector sizing mission.
- Why considered: broadens bench coverage without increasing vector size.

**Recommended for W628:** Variant A (`[75][2]^6 Pt`).
