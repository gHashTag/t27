## 0. What IGLA is

`IGLA` (Russian: "needle") is a **role**, not a new 28th agent. It acts as the
sharp probe of **Agent V (Verdict)** and **Agent E (Experience)**: find the
thinnest crack first, then drive a small fix through it. This audit is the
first run of the IGLA needle.

---

## 1. Executive Summary

The project is **technically prolific but operationally brittle**:

- **60+ wave-loops** of formal work exist; **only ~33% merged to master**.
- **5 CI checks are red** on every wave branch and are not fixed.
- The **compiler seal is stale** (`FROZEN_HASH` no longer matches `compiler.rs`)
  and `build.rs` does not enforce it.
- The **formal-to-hardware chain is disconnected**: proofs claim PVT-aware
  flash timing, but PVT coefficients are placeholders, real cold-POR is
  unimplemented, Vivado/scripts default to the wrong device, and the in-tree
  DLC10 driver targets a Xilinx cable VID while the bench uses Digilent FTDI.
- The **compiler** (`bootstrap/src/compiler.rs`) has grown to 27,746 lines,
  silently emits `0 /* TODO */` for unsupported aggregate lowering, and is
  surrounded by `.backup` / `.orig` files.
- **L4 TESTABILITY** is violated by many compiler specs; **L7 UNITY** is
  violated by shell scripts on the commit/push/CI critical path.

The biggest single risk is **loss of trust in the formal/hardware bridge**.
The second biggest is **merge paralysis** (red CI + seal drift + branch
backlog). Both are fixable incrementally.

## 2. P0 -- Critical Findings

### 2.1 Compiler seal is drifted and not enforced

- `bootstrap/stage0/FROZEN_HASH` line 1 pins:
  `49e55df6d444db18186f7e096b73ff56f77ae07d47547f1e5e64682a4999034d`
- Live SHA-256 of `bootstrap/src/compiler.rs` is
  `c02def71c591af65d5c926b40dd897ac4282e75ab3f4e11c0dadd6407df30c11`.
- `bootstrap/build.rs` only checks Cyrillic; it never reads `FROZEN_HASH`.
- `FROZEN.md` lines 7 and 95 claim `build.rs` verifies the seal -- false.

**Impact:** The bootstrap compiler's cryptographic baseline is decorative.

### 2.2 Issue gate can be bypassed by a duplicate workflow

- `.github/workflows/issue-gate.yml` (root) only matches `(closes|fixes|resolves) #[0-9]+`.
- `.github/workflows/workflows/issue-gate.yml` lines 22-28 always exits
  successfully, even when no issue is linked, and only matches `Fixes #N`.
- If branch protection points to the root name, GitHub may pick the duplicate.

**Impact:** L1 TRACEABILITY can be satisfied by a no-op.

### 2.3 Root-level CI workflows are stubs; real logic is in duplicate subdirectory

- `.github/workflows/schema-validation.yml` line 13-15: only prints.
- `.github/workflows/seal-coverage.yml` line 15-16: only prints.
- `.github/workflows/check-now-freshness.yml` line 14-16: placeholder comment.
- `.github/workflows/phi-loop-ci.yml` line 13-21: identity assert + grep only.
- Functional copies live under `.github/workflows/workflows/`.

**Impact:** Required status checks may be empty shells.

### 2.4 Formal hardware claims are built on placeholders and wrong targets

- `proofs/lean4/Trinity/TernaryFPGABoot.lean:590-606`: PVT derating
  coefficients documented as "pending Micron characterization".
- `proofs/lean4/Trinity/TernaryFPGABoot.lean:1196-1273`: "measured"
  CCLK theorems use synthetic nominal values, not oscilloscope captures.
- `cli/tri/src/fpga.rs:5999-6003`: real cold-POR relay control is
  unimplemented; only `--relay-port MOCK` works.
- `cli/tri/src/fpga.rs:7386-7388`: default `synth-gf16` chipdb is
  `xc7a100tfgg676.bin`, but default `--part` is `xc7a200tfbg676-1`.
- `fpga/vivado/build.tcl:1`, `build_gf16.tcl:1`, `build_gf16_matmul4x4.tcl:1`:
  all target `xc7a100tfgg676-1`; SSOT target is `xc7a200tfgg676-1`
  (`fpga/HARDWARE_SSOT.md`).
- `cli/dlc10/src/lib.rs:39`: `VID_XILINX = 0x03FD`; bench cable is Digilent
  FTDI `0x0403:0x6014`.
- `fpga/tools/bscan_spi_xc7a100t*.bit` target the wrong device.

**Impact:** The Lean proof tree is valid, but the evidence that would connect
it to the XC7A200T board is missing, stale, or hard-coded for the XC7A100T.

### 2.5 Active gen-verilog yosys regression in W469 scratch spec

- `specs/scratch/w469_2d_struct_array_param.t27` generates illegal Verilog:
  `0 /* TODO ... */ = 0 /* TODO ... */;`
- Root: `bootstrap/src/compiler.rs:6421-6544` and `8831-8862` lower
  unsupported aggregate literals to `0 /* TODO */`, producing illegal LHS.

**Impact:** Latest wave work has an unfixed codegen defect.

## 6. Root-Cause Synthesis

Five recurring roots explain most findings:

1. **Seal and policy are advisory, not enforced.** `build.rs`, CI gates, and
   hooks state rules but do not fail hard. The project optimizes for green
   commits over verified invariants.
2. **The compiler grew by accretion, not architecture.** 27k lines in one
   file, silent recovery, backup files in tree.
3. **FPGA evidence chain was built for a different board.** Early work
   targeted XC7A100T; SSOT now says XC7A200T. Scripts, bitstreams, drivers,
   and reports lag.
4. **Process favors opening waves over landing them.** 20 open wave-loop PRs
   and red CI checks persist because the loop does not stop for merge hygiene.
5. **Documentation and generated artifacts are not kept alive.** Reports,
   `NOW.md`, generated files, and numeric SSOT drift because no periodic
   scrubbing loop exists.
