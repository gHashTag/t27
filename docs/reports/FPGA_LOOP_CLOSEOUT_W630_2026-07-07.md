# FPGA Loop Closeout — Wave 630

**Issue:** #1601  
**Branch:** `wave-loop-630`  
**Date:** 2026-07-07  
**Variant:** A — `[79][2]^6 Pt` module-scope non-power-of-two outer-dimension array-of-struct, initialized from a function call, with indexed signed field writes and read-back.

---

## 1. Goal

Prove the t27 → Icarus lowering path can handle a module-scope mutable packed vector of outer dimension **79** (the next odd number after 77), where the variable is initialized by a function call and exercised with indexed signed writes to struct fields, then read back against a compile-time `expected` array.

---

## 2. Spec

- Witness: `specs/scratch/w630_bench_module_79x2p6_aos_var_call_write.t27`
- Type: `[79][2]^6 Pt` where `Pt { x: i16, y: i16 }`
- Total elements: 79 × 64 = **5,056**
- Packed vector width: 5,056 × 32 = **161,792 bits** (≈ **0.152 MiBit**)
- Spec size: ~15,100 lines (multi-line brace style required)

The module contains:

```t27
pub var dst: [79][2]^6 Pt = make_grid(0);
pub const expected: [79][2]^6 Pt = make_grid(0);
```

Both arrays are produced by a function `make_grid(offset: u16) -> [79][2]^6 Pt` that returns a fully expanded literal:

- Element value schedule: `(2*e + offset) % 32768` for `x`, `2*e + offset + 1` for `y`.
- Signed writes flip `x` and `y` to `-value` at selected indices.
- Read-back tests compare `dst` against `expected`.

### Chosen indices for corner coverage

Because offset 0 never wraps for 5,056 elements, an explicit `make_grid(32768)` assertion is kept in the spec to preserve the modulo-wrap regression signal.

| Index | Test | Raw values after write |
|---|---|---|
| `[0][0][0][0][0][0][0]` | first element | `0/1` (no write) |
| `[78][1][1][1][1][1][1]` | last element | `-10110/-10111` |
| `[39][1][0][0][0][0][0]` | middle element | `-5056/-5057` |

## 3. Implementation

### 3.1 Spec generation

The W630 witness was generated by extending the W629 (77-row) module-scope lowerable spec with two additional outer rows, advancing the sequential element values by 128/256 respectively for the `2*e`/`2*e+1` schedule.

### 3.2 Multi-line literal style

Following the W584/W605/W629 style, every `[2]^k Pt` level is written with line breaks to avoid parser truncation on extremely long single-line literals.

```t27
Pt{
    .x = 10110,
    .y = 10111
}
```

### 3.3 Integration test

Added to `bootstrap/tests/icarus_lowerable.rs`:


## 5. Weak points and literature

### Weak points

1. **Non-power-of-two outer dimension 79** — must be strided correctly by compiler and reference model.
2. **Modulo-wrap signal preservation** — 5,056 elements never wrap with offset 0; explicit `make_grid(32768)` assertions keep the path covered.
3. **Mega-literal parsing** — ~15,100-line spec needs multi-line brace style to avoid truncation.
4. **Simulator resource headroom** — 0.152 MiBit is far below the 4-MiBit freeze threshold but should still be monitored.
5. **Index/value correctness** — moving from 77 to 79 rows changes last-row index to 78 and mid-row index to 39.

### Technical literature

- [IEEE Std 1800-2017](https://ieeexplore.ieee.org/document/8299595/) packed-array semantics.
- Sutherland, *Synthesizable SystemVerilog* — packed struct/array support.
- [Icarus Verilog issue #1171](https://github.com/steveicarus/iverilog/issues/1171) — very-large packed-vector freeze threshold.
- Yosys issues [#2677](https://github.com/YosysHQ/yosys/issues/2677), [#4653](https://github.com/YosysHQ/yosys/issues/4653), PR [#4100](https://github.com/YosysHQ/yosys/pull/4100) — multidimensional packed arrays vs arrays of packed structs.
- cocotb `LogicArray` — reference-model mapping for packed arrays.
- Lutsig (CPP 2021) — verified array-read lowering.
- CIRCT `HWLegalizeModules.cpp` / SV dialect — scalarization of packed arrays.

## 6. Cooperation variants for Wave 631

### Variant A — `[81][2]^6 Pt` odd-outer ladder continuation (recommended)

- Outer dimension: 81.
- Total elements: 81 × 64 = 5,184.
- Packed width: 165,888 bits (≈0.155 MiBit).
- Risk: same module-scope lowerable style; direct extension of W630.
- Why recommended: maintains the established non-power-of-two pattern and is trivial to generate from W630.

### Variant B — `[2]^18 Pt` power-of-two deep dimension stress

- Outer dimension: 1; inner dimension: 2¹⁸.
- Total elements: 262,144.
- Packed width: 8,388,608 bits (8 MiBit).
- Risk: crosses the 4-MiBit Icarus freeze threshold; may require Yosys/Cocotb-only gate.
- Why considered: tests a very different shape and confirms the flattening path at a width that likely needs non-Icarus tooling.

### Variant C — conditional `if` reassignment in bench

- Keep `[79][2]^6 Pt` size but introduce an `if` statement inside the bench block that conditionally flips a subset of elements before comparison.
- Risk: exercises control-flow lowering in the bench harness, but may stray from the current wave’s pure packed-vector sizing mission.
- Why considered: broadens bench coverage without increasing vector size.

**Recommended for W631:** Variant A (`[81][2]^6 Pt`).
