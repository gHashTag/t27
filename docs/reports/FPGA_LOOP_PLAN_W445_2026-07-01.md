## 1. Weak points identified in W444

| Weak point | Why it matters | Where it lives |
|---|---|---|
| Fixtures live under `build/`, which is gitignored and ephemeral | CI cannot diff inputs/outputs between waves; a clean checkout loses the generated fixture set. | `build/fpga/theorem-matrix-fixtures/` |
| No checked-in golden fixture regression gate | A regression in `generate_theorem_matrix` or `replay_theorem_matrix` would only be caught by a fresh generation, not by a deterministic replay from a known-good set. | `cli/tri/src/fpga.rs` tests |
| Suite-level JSON summary does not expose FPGA smoke-gate timing | We cannot trend generation vs replay cost or detect performance regressions in CI. | `bootstrap/src/suite.rs` `SuiteSummary` |
| Synthetic fixtures only; no live fixture set | When the bench unblocks, there is no established pattern for persisting and replaying captured XADC fixtures. | `fpga/HARDWARE_SSOT.md` §3.6.26 |
| Issue #1418 still does not exist | HR-15 candidate rule: `Closes #N` must only be written after the issue is created. | commit messages |

This tightens the strategic threat: t27's ternary proof lattice is still differentiated in depth, but Sparkle's breadth is growing fast.
- **CIRCT / firtool**  
  - `firtool-1.152.0` (2026-07-04) remains the latest public release; no `1.153.0` has appeared.
- **Ternary FPGA ecosystem**

Strategic takeaway for W445: continue hardening the **machine-readable CI gate + deterministic fixture replay + measurable timing** because no competitor publishes a comparable sealed boot-evidence loop, and keep monitoring Sparkle for a spec-first sealed pipeline or physical measurement import path.

## 3. Decomposed implementation tasks

### 3.1 Commit a golden synthetic fixture set

1. Create `tests/fixtures/fpga/theorem-matrix/golden/`.
2. Copy the 24-variant fixture set generated by W444 into that directory:
   - 3 corner PVT files (`theorem_matrix_pvt_{ff,tt,ss}.json`)
   - 24 raw-ns files (`theorem_matrix_raw_ns_{corner}_{0..7}.json`)
   - 24 Lean files (`theorem_matrix_{corner}_oscfsel_{0..7}.lean`)
   - 24 summary files (`theorem_matrix_summary_{corner}_{0..7}.json`)
3. Add a short `README.md` explaining provenance and how to regenerate.

### 3.2 Add golden fixture replay regression test

1. In `cli/tri/src/fpga.rs` tests, add `test_theorem_matrix_golden_replay_passes` that:
   - resolves the fixture directory relative to `CARGO_MANIFEST_DIR`,
   - calls `replay_theorem_matrix`,
   - asserts 24 variants, all `envelope_check: "ok"`, and every variant has a `fixtures` block.
2. Ensure the test is deterministic and does not write into `build/`.

### 3.3 Add `elapsed_ms` metric to suite summary

1. Extend `bootstrap/src/suite.rs` so that when it parses the smoke-gate report,
   it reads `theorem_matrix.elapsed_ms` and includes an `fpga_smoke_gate_elapsed_ms`
   field in the suite-level `SuiteSummary` JSON.
2. Update `test_suite_summary_schema_roundtrip` and related tests to exercise the
   new field.
3. Keep the metric optional so older smoke-gate reports still parse.

### 3.4 Documentation refresh

1. Update `fpga/HARDWARE_SSOT.md` §3.6.26 to mention the golden fixture set and
   the checked-in regression path.
