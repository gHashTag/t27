# Wave Loop 503 — Cooperation Variants

**Date:** 2026-07-13  
**From:** Wave Loop 502 close-out (#1471, branch `wave-loop-502`)  
**Next ring:** 12 (gen-verilog / Icarus semantics)

Wave Loop 502 closed the non-`main` adversarial-witness boundary and generalized
the equivalence theorem to functions with parameters.  The next wave can either

connect the theorem to generated host test harnesses.

Each variant is scoped to one wave and lists the exact files/tests that would

## Variant A — Extend the equivalence proof to sequential constructs

**Goal:** add `ifThenElse` and `forLoop` to the Icarus-lowerable operational
semantics and the generic forward-simulation proof.

**Why now:**
- The theorem now covers any emitted function with any argument list, but only
  for purely combinational statements.
- Many practical t27 specs use simple `if` guards and bounded `for` loops.
- The entry-point and argument generalizations (W501/W502) leave `Stmt` as the
  only remaining major syntactic limitation.

**Work:**
1. In `proofs/lean4/Trinity/IcarusLowerable/SemanticsTotal.lean`, add total
   evaluation rules for `Stmt.ifThenElse` and `Stmt.forLoop` on both the t27
   and shallow-Verilog sides.  Model `if` as a valuation-level branch; model
   bounded `for` as repeated body execution with an induction variable.
2. In `proofs/lean4/Trinity/IcarusLowerable/Verilog.lean`, add shallow-Verilog
   statement constructors for `if` / `for` so the emitter can produce them.
3. In `proofs/lean4/Trinity/IcarusLowerable/Emitter.lean`, update `emitStmt` to
   emit real `if` / `for` nodes instead of concatenating both branches under
   `alwaysComb`/`initial`.
4. In `proofs/lean4/Trinity/IcarusLowerable/Predicate.lean`, broaden
   `Stmt.isCombinationalFuel` to allow `ifThenElse` and `forLoop` when their
   condition/range/body are combinational.
5. In `proofs/lean4/Trinity/IcarusLowerable/Equivalence.lean`, extend `all_equiv`
   with the `if` and `for` induction cases.
6. Add scratch witnesses:
   - `w503_if_return.t27` — conditional return of a numeric literal,
   - `w503_for_accumulator.t27` — bounded `for` summing into a local variable.
7. Re-run `./scripts/tri test`.

**Acceptance:**
- `lake build Trinity.IcarusLowerable.Soundness` green with zero `sorry`.
- At least two new scratch witnesses (conditional, for-loop) pass both t27 and
  emitted-Verilog evaluation.
- `./scripts/tri test` reports no new smoke failures.

## Variant B — Harden the classifier boundary with deeper adversarial witnesses

**Goal:** add witnesses on the remaining lowerability boundaries:
array-typed struct fields, host-only/helper classification, and imported
non-constructor calls.

**Why now:**
- W502 covered scalar-struct parameters and non-`main` call chains.
- The classifier still skips 294 specs with unmodeled placeholders.
- The boundary between "intentionally skipped" and "should be lowerable" is
  only as strong as the adversarial witness set.

**Work:**
1. Add scratch witnesses:
   - `w503_array_field_struct_param.t27` — helper taking a struct with an
     array-typed field (exercises memory-mode parameter packing),
   - `w503_host_only_helper_called.t27` — a module where a host-only helper is
     present but not emitted, proving the theorem only talks about emitted
     functions,
   - `w503_imported_non_ctor_call.t27` — an imported non-constructor function
     call that is lowerable,
   - `w503_unreachable_emitted_function.t27` — a function that is emitted but
     never called from `main` (uses W499's unconditional emission).
2. Run `./scripts/tri verify --lean-lowerable` and compare classifier verdicts
   with Icarus smoke results for every new witness.
3. If a witness passes smoke but the classifier says `not_lowerable`, extend
   `Predicate.lean`; if the classifier says `lowerable` but smoke fails, fix the
   emitter.
4. Add corresponding Lean witness modules and `native_decide` /
   `module_value_equiv_statement` theorems.
5. Reseal all new `.t27` witnesses.

**Acceptance:**
- At least four new adversarial scratch witnesses pass both the classifier and
  Icarus smoke.
- `./scripts/tri verify --lean-lowerable` reports zero disagreements.
- `./scripts/tri test` reports 183 / 183 Icarus smoke PASS and no new baseline
  failures.

## Variant C — Export the generalized theorem to generated host harnesses

**Goal:** make the C/Zig/Rust test harness generated by `t27c` aware of the
`module_value_equiv_statement` contract, so that unit tests targeting non-`main`
functions and functions with parameters are also covered by the Icarus
equivalence theorem.

**Why now:**
- W501/W502 proved that any emitted function preserves its value for any
  arguments.
- The generated host code currently runs `main` or ad-hoc helper calls against
  the emitted Verilog without linking those calls back to the formal contract.
- Closing this gap makes the formal model useful to the actual test harness,
  not only to hand-written Lean witnesses.

**Work:**
1. In `bootstrap/src/compiler.rs`, record the list of emitted (non-host-only)
   functions and their parameter/return widths in the generated conformance /
   test metadata.
2. In the generated Zig/C host harness, emit a manifest entry that maps each
   public non-host-only function to the `module_value_equiv_statement`
   instance that applies to it.
3. Add a conformance snapshot test that checks the emitted manifest lists at
   least one non-`main` emitted function and one function with parameters.
4. Add a scratch `.t27` module where the test block calls a helper directly with
   an argument, and verify the manifest captures it.

**Acceptance:**
- Generated host test metadata contains an `icarus_equiv_functions` list with
  every emitted function name and its signature.
- A non-`main` function and a function with a parameter appear in the list and
  pass Icarus smoke.
- `./scripts/tri test` reports no regressions.

## Suggested priority

1. **Variant A** — widens the modeled subset and is the next logical proof step.
2. **Variant B** — defensive hardening that can run in parallel with A or as a
   standalone wave if A uncovers model-alignment issues.
3. **Variant C** — connects the formal theorem to the generated host harness;
   most valuable once the modeled subset (A) and boundary (B) are stable.
