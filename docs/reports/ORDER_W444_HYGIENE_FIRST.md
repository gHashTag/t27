## 3. PR-stack drain order

Goal: get W437–W441 into `master` before merging W443, so W443 can be rebased on
clean master and does not inherit stale divergence.

### 3.1 Inspect each PR

```bash
for n in 1408 1410 1412 1414 1416; do
  echo "=== PR #$n ==="
  gh pr view $n --json number,state,mergeable,mergeableState,headRefName,baseRefName,commits,files
  echo
done
```

### 3.2 Default drain strategy (sequential merge)

Merge in wave order. Each merge updates `master`, so the next PR can be rebased
or merged on top:

```bash
gh pr merge 1408 --squash --delete-branch=false
git fetch origin
for n in 1410 1412 1414 1416; do
  gh pr merge $n --squash --delete-branch=false
done
```

**Important:** after each merge, verify the next PR is still mergeable and CI is
green. If any PR is `mergeableState: BLOCKED` or has conflicts, stop and switch
to the consolidation strategy below.

### 3.3 Fallback consolidation strategy (if sequential merge conflicts)

If W438–W441 conflict because they touch the same files (typical for the FPGA
CLI stack), create a consolidated branch from `master` and cherry-pick the wave
commits in order:

```bash

git pull origin master
git checkout -b order-w437-w441-consolidated
for b in wave-loop-437 wave-loop-438 wave-loop-439 wave-loop-440 wave-loop-441; do
  git merge origin/$b --no-ff -m "consolidated: merge $b into order-w437-w441-consolidated"
done
```

Then close the individual PRs with a reference comment and open a single
consolidated PR:

